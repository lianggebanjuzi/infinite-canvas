Infinite Canvas 卡片开发规则 v2.0
本文档定义了新增卡片类型时必须遵循的信息流转规范，确保所有卡片无缝融入现有架构。

适用范围：新增任意卡片类型（继承 BaseCard）。

核心原则：通过契约声明驱动数据流转，通过事件总线解耦通信，通过规则引擎处理 UI 效果，通过脏队列批量合并推送。

1. 必遵流程：新增卡片的步骤
每新增一张卡片，必须完成以下全部步骤：

步骤 1  →  继承 BaseCard，声明 getType()
步骤 2  →  声明静态 getContract() 契约（含类型、端口、通知策略）
步骤 3  →  实现 getOutput(outputName) 获取输出数据
步骤 4  →  实现 onReceive(type, data, meta) 接收上游数据
步骤 5  →  数据变化时调用 this.notifyDownstream(source) 推送下游
          （由 DirtyQueue 合并后统一发布 DATA_CHANGED）
步骤 6  →  运行完成时调用 this.completeRun(outputData) 推送结果
          （由 BaseCard 根据 Contract.notifyOn 自动选择事件类型）
步骤 7  →  实现 serialize() / constructor 反序列化，包含 _version 字段
步骤 8  →  在 CardFactory.create() 中注册类型分支
步骤 9  →  在 event-bus-init.js 中注册事件订阅（如需要）
步骤 10 →  在 ConnectionRules.js 中注册连接钩子（仅 UI 效果，如需要）
推送原则：

数据变化时统一调用 this.notifyDownstream(source)，由 DirtyQueue 在微任务中合并、拓扑排序后统一推送，避免菱形依赖重复触发。
不要在卡片内部直接调用下游卡片的方法。
不要在卡片内部直接 emit 事件，统一走 notifyDownstream() 或 completeRun()。

2.2 类型系统
类型采用 MIME 风格的层级结构，匹配时支持通配：

类型字符串	含义	匹配规则
text/plain	纯文本	精确匹配，或被 text/* 匹配
text/json	结构化 JSON 文本	精确匹配，或被 text/* 匹配
text/*	任意文本	通配，匹配所有 text/ 开头的类型
image/base64	Base64 编码图片	精确匹配，或被 image/* 匹配
image/url	图片 URL（http/file）	精确匹配，或被 image/* 匹配
image/*	任意图片	通配，匹配所有 image/ 开头的类型
向后兼容：旧的 'text' 等价于 'text/plain'，'image' 等价于 'image/base64'。CardContract.isTypeMatch() 内部自动处理这层映射。

Copy// CardContract.js 中的类型匹配逻辑
static isTypeMatch(outputType, inputType) {
    // 向后兼容：旧类型映射（两端都要 normalize）
    const normalize = (t) => {
        if (t === 'text')  return 'text/plain';
        if (t === 'image') return 'image/base64';
        return t;
    };

    const out = normalize(outputType);
    const inp = normalize(inputType);

    // 精确匹配
    if (out === inp) return true;

    // 通配匹配：input 声明 'image/*'，output 为 'image/base64' → 匹配
    if (inp.endsWith('/*')) {
        const prefix = inp.slice(0, -1); // 'image/'
        return out.startsWith(prefix);
    }

    return false;
}
2.3 receivePolicy 接收策略
策略值	含义	使用场景
replace	替换（默认）	单输入：收到新数据直接替换旧数据
append	追加（按连线 ID 做 upsert）	多输入：从多个上游累积数据
ignore	忽略	需要手动从连线状态读取，不走通用引擎
append 策略的身份追踪：onReceive() 的 meta 参数中包含 sourceCardId 和 connectionId。 使用 append 策略时，应以 connectionId 为 key 做 upsert，而不是盲目 push。 断线时按 connectionId 精确移除对应数据，无需全量刷新。

2.4 notifyOn 通知策略
策略值	含义	使用场景
onChange	默认。数据变化时立即通知下游	TextCard、ImageInputCard 等输入类卡片
onRun	仅在运行完成后通知下游	AIDrawCard 等生成类卡片
onApply	仅在用户点击"应用"按钮后通知下游	DrawingBoardCard 等画板类卡片
重要：子类不需要自己判断发 DATA_CHANGED 还是 RUN_COMPLETED。 调用 this.notifyDownstream(source) 会发 DATA_CHANGED， 调用 this.completeRun(outputData) 会根据 notifyOn 自动选择事件类型。 详见 3.3 统一推送入口。

2.5 getDataType() 静态方法
BaseCard 提供了默认实现，会自动从 getContract().outputs[0].type 读取。如果卡片有多个输出类型，需手动覆盖：

Copystatic getDataType() {

    if (!contract.outputs.length) return null;
    return contract.outputs.find(o => o.name === 'default')?.type || null;

3.2 事件互斥规则
DATA_CHANGED 和 RUN_COMPLETED 是互斥的，由框架自动保证：

场景	调用方法	框架发出的事件	示例
被动数据变化（编辑、上游推送）	this.notifyDownstream(source)	DATA_CHANGED	TextCard 输入框内容变化
主动运行完成	this.completeRun(outputData)	根据 notifyOn 自动选择	AIDrawCard 生成完成
子类永远不要直接调用 CardEventBus.emit()。 统一通过 notifyDownstream() 和 completeRun() 间接发布事件。

3.3 统一推送入口（BaseCard 提供的两个方法）
Copy// ── BaseCard.js ──

/**
 * 被动推送：数据变化时调用（编辑、上游推送后）
 * 不会立即推送，而是进入 DirtyQueue，在微任务中合并后统一推送
 */
notifyDownstream(source = 'upstream') {
    DirtyQueue.enqueue(this, source);
}

/**
 * 主动推送：运行完成时调用
 * 根据 Contract 中的 notifyOn 自动选择事件类型
 */
completeRun(outputData) {
    this._outputCache = outputData;

    const contract = this.constructor.getContract();
    const output = contract.outputs?.[0];
    const notifyOn = output?.notifyOn || 'onChange';

    // notifyOn 为 'onRun' 或 'onApply' 时发 RUN_COMPLETED
    // notifyOn 为 'onChange' 时发 DATA_CHANGED（通过 DirtyQueue）
    if (notifyOn === 'onRun' || notifyOn === 'onApply') {
        CardEventBus.emit(CardEventBus.EventTypes.RUN_COMPLETED, {
            cardId: this.id,
            type: output.type,
            data: outputData,
            source: 'run'
        });
    } else {
        this.notifyDownstream('run');
    }
}

注意：`completeRun` 固定取 `outputs[0]` 推送第一个端口的数据。如果卡片有多个输出端口需要分别推送，应手动构造事件或多次调用，并确保通知策略与契约一致。

3.7 订阅生命周期管理
卡片销毁时必须取消所有订阅，防止内存泄漏。

BaseCard 在 destroy() 中自动处理：

Copy// ── BaseCard.js ──

constructor(options) {
    // ...
    this._subscriptionIds = []; // 记录所有订阅 ID
}

/**
 * 封装订阅方法，自动追踪订阅 ID
 */
subscribe(eventType, handler, filter) {
    const id = CardEventBus.subscribe(eventType, handler, filter);
    this._subscriptionIds.push(id);
    return id;
}

/**
 * 销毁卡片时自动取消所有订阅
 */
destroy() {
    this._subscriptionIds.forEach(id => CardEventBus.unsubscribe(id));
    this._subscriptionIds = [];
    DirtyQueue.remove(this.id); // 清除脏队列中的残留
    super.destroy();
}
规范：子类中如果需要订阅事件，使用 this.subscribe() 而不是直接调用 CardEventBus.subscribe()。 这样 destroy() 时会自动清理。

4. DirtyQueue 批量推送引擎
4.1 解决的问题
问题	原因	DirtyQueue 如何解决
菱形依赖重复推送	同一个下游被两条路径分别触发	微任务中去重，每个卡片只推一次
链路雪崩	上游一变，逐级同步推到底	按拓扑序批量推送，不逐级递归
无意义的中间状态渲染	中间节点的临时输出触发下游重绘	合并后只推送最终状态
4.2 工作原理
卡片 A 数据变化
  → A 调用 this.notifyDownstream()
    → DirtyQueue.enqueue(A)
      → 标记 A._dirty = true
      → 如果尚未调度，注册一个 queueMicrotask

（同一事件循环中，卡片 B 也变化了）
  → DirtyQueue.enqueue(B)
    → 标记 B._dirty = true
    → 已经调度过，不重复注册

（当前同步代码执行完毕，微任务触发）
  → DirtyQueue._flush()
    → 对队列中所有卡片做拓扑排序
    → 去重（同一卡片只保留一次）
    → 按拓扑序依次：
        → card._dirty = false
        → CardEventBus.emit(DATA_CHANGED, { ... })
        → ConnectionRules.applyOnDataChanged(card, ...)
          → 遍历下游连线，调用 downstream.onReceive()
          → 如果 downstream 在处理后也调了 notifyDownstream()
             → 进入下一轮 DirtyQueue（不会在本轮 flush 中处理）
4.3 完整实现
Copy// ── gui/js/cards/DirtyQueue.js ──

class DirtyQueue {

    static _queue = [];
    static _scheduled = false;
    static _cardSet = new Set(); // 用于快速去重

    /**
     * 将卡片加入脏队列
     * @param {BaseCard} card   - 数据发生变化的卡片
     * @param {string}   source - 变化来源：'upstream' | 'manual' | 'run'
     */
    static enqueue(card, source = 'upstream') {
        // 如果该卡片已经在队列中，只更新 source（不重复入队）
        if (this._cardSet.has(card.id)) {
            const existing = this._queue.find(item => item.card.id === card.id);
            if (existing) existing.source = source;
            return;
        }

        this._queue.push({ card, source });
        this._cardSet.add(card.id);

        if (!this._scheduled) {
            this._scheduled = true;
            queueMicrotask(() => this._flush());
        }
    }

    /**
     * 从队列中移除指定卡片（用于卡片销毁时清理）
     */
    static remove(cardId) {
        this._queue = this._queue.filter(item => item.card.id !== cardId);
        this._cardSet.delete(cardId);
    }

    /**
     * 微任务中执行：拓扑排序 → 去重 → 依次推送
     */
    static _flush() {
        const batch = [...this._queue];
        this._queue = [];
        this._cardSet.clear();
        this._scheduled = false;

        // 按拓扑序排序（上游在前，下游在后）
        const sorted = this._topoSort(batch);

        // 依次推送
        for (const { card, source } of sorted) {
            // 卡片可能在 flush 期间被销毁
            if (!card.element || card._destroyed) continue;

            const contract = card.constructor.getContract();
            const output = contract.outputs?.[0];
            if (!output) continue;

            const data = card.getOutput?.() ?? null;

            CardEventBus.emit(CardEventBus.EventTypes.DATA_CHANGED, {
                cardId: card.id,
                type: output.type,
                data: data,
                source: source
            });
        }
    }

    /**
     * 拓扑排序：根据 AppState.connections.list 构建依赖关系
     * 保证上游卡片先推送，下游卡片后推送。
     * 注意：Kahn 算法只能处理 DAG（有向无环图）。如果存在循环依赖，
     * 循环中的卡片会追加到末尾，处理顺序不确定。正常业务中应避免循环连线。
     */
    static _topoSort(batch) {
        if (batch.length <= 1) return batch;

        const connections = AppState.connections.list;
        const batchIds = new Set(batch.map(item => item.card.id));
        const itemMap = new Map(batch.map(item => [item.card.id, item]));

        // 构建入度表（只统计 batch 内部的依赖）
        const inDegree = new Map();
        const adjList = new Map();

        for (const id of batchIds) {
            inDegree.set(id, 0);
            adjList.set(id, []);
        }

        for (const conn of connections) {
            if (batchIds.has(conn.start) && batchIds.has(conn.end)) {
                adjList.get(conn.start).push(conn.end);
                inDegree.set(conn.end, (inDegree.get(conn.end) || 0) + 1);
            }
        }

        // Kahn 算法
        const queue = [];
        for (const [id, deg] of inDegree) {
            if (deg === 0) queue.push(id);
        }

        const result = [];
        while (queue.length > 0) {
            const id = queue.shift();
            result.push(itemMap.get(id));
            for (const neighbor of (adjList.get(id) || [])) {
                inDegree.set(neighbor, inDegree.get(neighbor) - 1);
                if (inDegree.get(neighbor) === 0) {
                    queue.push(neighbor);
                }
            }
        }

        // 如果有不在拓扑图中的卡片（无依赖关系或循环依赖），追加到末尾
        // 循环依赖的卡片会落在这里，处理顺序不确定
        for (const item of batch) {
            if (!result.includes(item)) {
                result.push(item);
            }
        }

        return result;
    }
}

5. ConnectionRules 规则引擎
5.1 核心原则
ConnectionRules 钩子只做纯 UI 效果，绝不传递数据。

所有数据传递统一通过 onReceive(type, data, meta) 处理。 包括多端口卡片的端口路由，也在 onReceive 的 meta.endPort 中处理。

Copyfunction waitAndSubscribe(timeout) {
    if (typeof CardEventBus === 'undefined' ||
        typeof CardFactory === 'undefined' ||
        typeof ConnectionRules === 'undefined' ||
        typeof DirtyQueue === 'undefined') {
        if (timeout > 0) {

function _doSubscribe() {
    // 订阅 DATA_CHANGED：由 DirtyQueue flush 后触发
    CardEventBus.subscribe(
        CardEventBus.EventTypes.DATA_CHANGED,
        (event) => {
            const card = CardFactory.getInstance(event.cardId);
            if (!card) return;
            ConnectionRules.applyOnDataChanged(card, event.type, event.data);
        }
    );

    // 订阅 RUN_COMPLETED：由 completeRun() 触发
    CardEventBus.subscribe(
        CardEventBus.EventTypes.RUN_COMPLETED,
        (event) => {
            const card = CardFactory.getInstance(event.cardId);
            if (!card) return;
            ConnectionRules.applyOnRunCompleted(card, event.type, event.data);
        }
    );
}

11. 完整示例：新增一个 FilterCard
假设我们要新增一个 FilterCard，功能是对图片应用滤镜后输出。

11.1 契约设计
输入：image/*（任意图片格式）
输出：image/base64（应用滤镜后的 Base64 图片）
通知策略：onRun（用户点击"应用"后才推送）
11.2 实现代码
Copy// gui/js/cards/FilterCard.js

class FilterCard extends BaseCard {

    // 当前序列化版本
    static CURRENT_VERSION = 1;

    constructor(options = {}) {
        super({
            width:  '400px',
            height: '360px',
            title:  'Filter',
            ...options
        });

        // 默认值
        this.filterType = 'grayscale';
        this.inputImage = '';
        this.outputImage = '';

        // 用于 append 策略的输入映射（本卡片用 replace，此处仅做示范）
        // this._inputMap = new Map();

        // 从 content 恢复
        if (options.content) {
            try {
                const parsed = JSON.parse(options.content);
                this._migrateState(parsed);
            } catch {}
        }

        // 从 options 直接恢复
        if (options.filterType) this.filterType = options.filterType;
        if (options.inputImage) this.inputImage = options.inputImage;
        if (options.outputImage) this.outputImage = options.outputImage;

        // 版本迁移
        if (options._version !== undefined) {
            this._migrateState(options);
        }
    }

    // ─────────────────────────────────────────
    // 版本迁移
    // ─────────────────────────────────────────
    _migrateState(state) {
        let version = state._version || 0;

        if (version < 1) {
            // v0 → v1：兼容旧的 filter 字段名
            state.filterType = state.filter || state.filterType || 'grayscale';
            delete state.filter;
            version = 1;
        }

        this.filterType = state.filterType || 'grayscale';
    }

    // ─────────────────────────────────────────
    // 1. getType()
    // ─────────────────────────────────────────
    getType() { return 'filter'; }

    // ─────────────────────────────────────────
    // 2. 契约声明
    // ─────────────────────────────────────────
    static getContract() {
        return {
            outputs: [{
                name: 'default',
                type: 'image/base64',
                notifyOn: 'onRun'   // 用户点击"应用"后才推送
            }],
            inputs: [{
                name: 'image',
                type: 'image/*',            // 接受任意图片格式
                receivePolicy: 'replace'
            }]
        };
    }

    // ─────────────────────────────────────────
    // 3. getOutput() — 返回输出数据
    // ─────────────────────────────────────────
    getOutput(outputName = 'default') {
        if (outputName === 'default') {
            return this.outputImage || null;
        }
        return null;
    }

    // ─────────────────────────────────────────
    // 4. onReceive() — 接收上游数据（v2.0 签名）
    // ─────────────────────────────────────────
    onReceive(type, data, meta = {}) {
        if (CardContract.isTypeMatch(type, 'image/*') && data) {
            this.inputImage = data;
            this._renderOutput();
            // 注意：不在这里调用 _applyFilter()
            // 因为 notifyOn 是 'onRun'，需要用户手动点击"应用"
        }
    }

    // ─────────────────────────────────────────
    // 5. _applyFilter() — 应用滤镜
    // ─────────────────────────────────────────
    _applyFilter() {
        if (!this.inputImage) return;

        const img = new Image();
        img.onload = () => {
            const canvas = document.createElement('canvas');
            canvas.width  = img.width;
            canvas.height = img.height;
            const ctx = canvas.getContext('2d');

            ctx.filter = this._getCssFilter();
            ctx.drawImage(img, 0, 0);

            this.outputImage = canvas.toDataURL('image/png');
            this._renderOutput();

            // ✅ 通过 completeRun() 推送，框架自动根据 notifyOn 选择事件类型
            this.completeRun(this.outputImage);
        };
        img.src = this.inputImage;
    }

    _getCssFilter() {
        const filters = {
            'grayscale':  'grayscale(100%)',
            'blur':       'blur(5px)',
            'brightness': 'brightness(1.5)',
            'sepia':      'sepia(100%)',
        };
        return filters[this.filterType] || 'none';
    }

    // ─────────────────────────────────────────
    // 6. renderContent() — 渲染卡片内容
    // ─────────────────────────────────────────
    renderContent() {
        return `
            <div class="filter-preview">
                ${this.outputImage
                    ? `<img src="${this.outputImage}" class="filter-result">`
                    : (this.inputImage
                        ? `<img src="${this.inputImage}" class="filter-input-preview">`
                        : '<div class="filter-placeholder">等待输入图片</div>'
                    )
                }
            </div>
            <div class="filter-controls">
                <select class="filter-select" onchange="FilterCard.setFilter('${this.id}', this.value)">
                    <option value="grayscale" ${this.filterType === 'grayscale' ? 'selected' : ''}>灰度</option>
                    <option value="blur"       ${this.filterType === 'blur'       ? 'selected' : ''}>模糊</option>
                    <option value="brightness" ${this.filterType === 'brightness' ? 'selected' : ''}>变亮</option>
                    <option value="sepia"       ${this.filterType === 'sepia'       ? 'selected' : ''}>复古</option>
                </select>
                <button class="filter-apply-btn" onclick="FilterCard.apply('${this.id}')">应用</button>
            </div>
        `;
    }

    _renderOutput() {
        const body = this.element?.querySelector('.card-body');
        if (!body) return;
        body.innerHTML = this.renderContent();
    }

    // ─────────────────────────────────────────
    // 7. serialize() — 序列化（含版本号）
    // ─────────────────────────────────────────
    serialize() {
        const base = super.serialize();
        return {
            ...base,
            _version: FilterCard.CURRENT_VERSION,
            filterType: this.filterType,
            inputImage: this.inputImage,
            outputImage: this.outputImage,
            content: JSON.stringify({
                _version: FilterCard.CURRENT_VERSION,
                filterType: this.filterType
            })
        };
    }
}

// ─────────────────────────────────────────
// 静态方法（供 HTML onclick 调用）
// ─────────────────────────────────────────
FilterCard.setFilter = function (cardId, filterType) {
    const card = CardFactory.getInstance(cardId);
    if (!card) return;
    card.filterType = filterType;
    card._renderOutput();
};

FilterCard.apply = function (cardId) {
    const card = CardFactory.getInstance(cardId);
    if (!card) return;
    if (card.inputImage) {
        card._applyFilter();
    } else {
        Toast.show('请先连接图片输入卡片');
    }
};

12. 常见问题排查
Q1: 连线建立后，下游卡片没有收到数据
排查步骤：

确认源卡片声明了 outputs（不为空数组）
确认目标卡片声明了匹配的 inputs（类型通配匹配，如 image/base64 匹配 image/*）
确认目标卡片实现了 onReceive(type, data, meta) 方法（注意 v2.0 签名）
检查浏览器控制台是否有 [ConnectionRules] Hook error 报错
确认 event-bus-init.js 中已注册 DATA_CHANGED 和 RUN_COMPLETED 的订阅
Q2: 断开连线后，下游卡片的界面没有更新
排查步骤：

确认目标卡片实现了 refreshUpstream() 方法
确认 ConnectionRules.applyOnDisconnect() 中调用了 targetCard.refreshUpstream()
refreshUpstream() 必须从 AppState.connections.list 重新读取连线状态
如果使用 append 策略，确认按 connectionId 做了精确移除
Q3: 同一数据被添加了两次（如缩略图出现两个）
原因：连接时既在 ConnectionRules 钩子中传递了数据，又在 onReceive() 中处理了数据。

解决：检查 ConnectionRules 钩子是否违反了"只做纯 UI 效果"的原则。所有数据传递必须只走 onReceive()。

Q4: 菱形依赖导致下游被触发多次
原因：未使用 DirtyQueue，或直接调用了 CardEventBus.emit() 绕过了 DirtyQueue。

解决：确认所有推送都通过 this.notifyDownstream() 或 this.completeRun() 触发，不直接 emit 事件。

Q5: 图片卡片输出后，下游 PreviewCard 显示空白
原因：getOutput() 返回了 file:// 路径，但下游需要 data:image URL。

解决：

卡片内部缓存一个 _displayDataUrl 字段，始终存储可用的 data URL
getOutput() 优先返回 _displayDataUrl
在 Contract 中使用精确类型（image/base64 vs image/url）以避免格式不匹配
Q6: 新卡片在拖拽/缩放时报错
原因：子类的 createElement() 中使用了自定义 DOM 结构，端口元素缺失。

解决：在子类的 createElement() 中先调用 super.createElement()，然后再操作 DOM。

Q7: 序列化/反序列化后卡片状态丢失
排查步骤：

确认 serialize() 中包含了 _version 字段和所有必要状态
确认 constructor 中通过 _migrateState() 做了版本迁移
确认迁移链路完整（v0 → v1 → v2 → ...），没有跳版本
确认 CardFactory.loadCards() 调用时传入了正确的 options
Q8: 卡片删除后内存泄漏
排查步骤：

确认使用了 this.subscribe() 而非直接 CardEventBus.subscribe()
确认 destroy() 中调用了 super.destroy()
用浏览器 DevTools 的 Memory 面板做快照对比，检查是否有残留引用
