## 一、设计原则

### 1.1 核心原则

**① 单一职责原则（SRP）**
每个模块（文件、类、函数）只做一件事。

- ✅ `Clipboard.copy()` 只负责复制
- ✅ `Clipboard.paste()` 只负责粘贴
- ❌ 不要在 `Clipboard` 里做历史记录（交给调用方）

**② 不要重复自己（DRY）**
相同的逻辑只出现一次。

- ✅ 统一使用 `CardFactory.getInstance().serialize()` 获取卡片数据
- ❌ 不要在多处手写相同的卡片遍历逻辑

**③ 面向接口编程**
通过公开 API 交互，不直接访问内部实现。

- ✅ 通过 `CardFactory.create()` 创建卡片
- ✅ 通过 `UndoRedo.save()` 保存快照
- ❌ 不要直接修改 `AppState.cards.list`

**④ 渐进式增强**
不追求一步到位的完美架构，但要保证每次改动都是净改进。

### 1.2 状态管理原则

**原则：状态是数据，操作是方法**

```javascript
// ✅ 正确：状态就是纯数据
window.AppState.cards = {
    activeCardId: null,
    multiSelected: []
};

// ✅ 正确：通过方法操作状态
CardFactory.deselectAll();  // 内部修改 AppState.cards

// ❌ 错误：状态里混入复杂对象
window.AppState.ai = {
    generatingCards: new Map(),  // ❌ 复杂对象，不属于纯状态定义
    connectionUpdateQueue: new Set()  // ❌ 同上
};

// ✅ 更好：将复杂对象移到专门的管理器
window.AIGenerator = {
    _generatingCards: new Map(),
    // ...
};
```

**原则：访问状态通过 API，不直接操作**

```javascript
// ❌ 错误：直接操作 AppState
AppState.canvas.contextClickPos = pos;
AppState.laser.justFinished = false;

// ✅ 正确：通过模块 API
Canvas.setContextClickPos(pos);
Laser.setJustFinished(false);

// ❌ 错误：访问未定义的状态属性（运行时错误）
if (AppState.editor.activeCardId === cardId) { ... }  // AppState.editor 从未定义

// ❌ 错误：访问未定义的类属性（条件永远为假）
if (ImageInputCard._modalState) return;  // _modalState 从未定义

// ✅ 正确：需要跨模块状态时，通过事件总线或专门的状态访问器
CardEventBus.emit(CardEventBus.EventTypes.IMAGE_EDITOR_OPEN, { cardId });
```

### 2.2 新增文件规范

**新增文件前先判断归属：**

| 判断问题 | 归属目录 |
|----------|----------|
| 需要操作 DOM 吗？ | `components/` |
| 需要与其他卡片交互吗？ | `cards/` |
| 需要保存/加载数据吗？ | `core/` 或 `services/` |
| 是纯函数、无副作用吗？ | `utils/` |
| 是全局状态吗？ | `state/` + 聚合到 `state.js` |

**命名规范：**
- 目录：小写 + 连字符（`components/`、`services/`）
- 文件： kebab-case（`clipboard.js`、`undo-redo.js`）
- 类名： PascalCase（`CardFactory`、`UndoRedo`）
- 枚举/常量： UPPER_SNAKE_CASE（`CardEventBus.EventTypes`）

## 三、卡片系统规范

### 3.1 新增卡片类型流程

**Step 1：在 CardFactory 中注册**

```javascript
// cards/CardFactory.js
create(type, options = {}, saveHistory = true) {
    let card;
    switch (type) {
        // ... 现有类型 ...
        case 'my-card':
            card = new MyCard(options);
            break;
        default:
            console.warn(`未知卡片类型: ${type}`);
            return null;
    }
    // ... 后续逻辑不变 ...
}
```

**Step 2：创建卡片类文件**

```javascript
// cards/MyCard.js
class MyCard extends BaseCard {

    constructor(options = {}) {
        super({
            width:  '200px',
            height: '160px',
            title:  'My Card',
            ...options
        });
        // 初始化自有属性
    }

    getType() {
        return 'my-card';  // 与 CardFactory 中的 type 一致
    }

    renderContent() {
        // 返回 HTML 字符串或 DOM 元素
        return '<div>卡片内容</div>';
    }

    // 契约声明（必须）
    static getContract() {
        return {
            outputs: [{ name: 'default', type: 'text' }],  // 输出什么
            inputs: []  // 接受什么输入
        };
    }

    getOutput(outputName = 'default') {
        return '输出数据';
    }

    // 序列化（必须）
    serialize() {
        const base = super.serialize();
        return {
            ...base,
            content: this.content || ''
        };
    }

    // 接收数据（可选）
    onReceive(type, data, source) {
        // 处理上游推送的数据
    }
}

window.MyCard = MyCard;
```

**Step 3：添加类型标签（可选）**

在 `cards/BaseCard.js` 的 `typeLabels` 中添加：

```javascript
const typeLabels = {
    // ... 现有 ...
    'my-card': 'My Card'
};
```

**Step 4：在 HTML 中引入**

在 `index.html` 的卡片脚本区域添加：

```html
<script src="js/cards/MyCard.js"></script>
```

### 3.2 卡片序列化规范

**原则：每个卡片负责序列化自己的数据**

```javascript
// ✅ 正确：卡片类负责自己的序列化
MyCard.serialize() {
    const base = super.serialize();
    return {
        ...base,
        // 添加自己的字段
        customField: this.customField
    };
}

// ❌ 错误：在 CardFactory 或其他地方手写卡片字段
function collectCards() {
    cards.forEach(card => {
        if (card.getAttribute('data-type') === 'my-card') {
            // ❌ 不要在这里手写字段
            return { id, type, customField: ... };
        }
    });
}
```

**serialize() 的责任：**
- 返回卡片完整数据（包含所有需要保存/恢复的字段）
- 不负责 base64 占位符处理（由 SnapshotCollector 统一处理）
- 不负责 ID 生成（ID 在 CardFactory.create() 时确定）

### 3.3 卡片间通信规范

**方式 1：通过 ConnectionRules（推荐）**

卡片定义契约，ConnectionRules 自动处理数据流：

```javascript
// AIDrawCard 声明接收 text 和 image
static getContract() {
    return {
        outputs: [{ name: 'default', type: 'image' }],
        inputs: [
            { name: 'text', type: 'text' },
            { name: 'ref', type: 'image', multiple: true }
        ]
    };
}

// 实现 onReceive 处理数据
onReceive(type, data, sourceId) {
    if (type === 'text') {
        this.prompt = data;
    } else if (type === 'image') {
        this.addRefImage(sourceId, data);
    }
}
```

**方式 2：通过 CardEventBus（事件驱动）**

```javascript
// 发布事件
CardEventBus.emit(CardEventBus.EventTypes.DATA_CHANGED, {
    cardId: this.id,
    type: 'image',
    data: imageData
});

// 订阅事件（在 event-bus-init.js 中）
CardEventBus.on(CardEventBus.EventTypes.DATA_CHANGED, (event) => {
    // 处理事件
});
```

**方式 3：直接引用（谨慎使用）**

```javascript
// 谨慎使用，只在必要时使用
const targetCard = CardFactory.getInstance(cardId);
targetCard?.doSomething();
```

## 四、连接规则规范

### 4.1 添加新连接规则

**场景：需要在新卡片类型之间建立连接时**

```javascript
// cards/ConnectionRules.js

// 1. 通用契约规则：自动处理数据流（通常不需要写代码）
// ConnectionRules 会根据 getContract() 自动匹配

// 2. 生命周期钩子：需要 UI 效果时使用
ConnectionRules.register('my-source→my-target', (sourceCard, targetCard) => {
    // 连接时执行
    targetCard.updateUI?.();
});

// 连接时和断开时逻辑相同，可以只注册一个钩子
// applyOnDisconnect 会自动调用 refreshUpstream
```

**规则：**
- ✅ 使用契约系统处理数据流（自动匹配）
- ✅ 只在需要 UI 效果时使用钩子
- ❌ 不要在钩子里调用 `onReceive`（会重复）
- ❌ 不要在多处写相同逻辑

---

### 4.2 规则设计原则

**按类型匹配，不按卡片逐对注册：**

```javascript
// ✅ 正确：按类型匹配
// text 类型 → ai-image 类型：禁用输入框
ConnectionRules.register('text→ai-image', handler);

// ❌ 错误：按具体卡片注册
ConnectionRules.register('card-123→card-456', handler);
```

**钩子只做"不需要数据的 UI 更新"：**

```javascript
// ✅ 正确：纯 UI 效果
ConnectionRules.register('text→ai-image', (source, target) => {
    target.disableInput?.();
});

// ❌ 错误：处理数据（应由契约引擎处理）
ConnectionRules.register('text→ai-image', (source, target) => {
    target.prompt = source.output;  // ❌ 不要这样做
});
```

## 五、快照与历史规范

### 5.1 快照收集规范

**统一通过 SnapshotCollector 收集快照：**

```javascript
// ✅ 正确：使用 SnapshotCollector
const snapshot = SnapshotCollector.collect({
    sanitizeBase64: true,   // 撤销快照：替换 base64
    includeCanvas: true
});

// ❌ 错误：手写遍历逻辑
document.querySelectorAll('.card').forEach(card => {
    const instance = CardFactory.getInstance(card.id);
    // ... 手写收集逻辑 ...
});
```

### 5.2 何时保存快照

| 操作 | 是否保存 | 原因 |
|------|----------|------|
| 创建卡片 | ✅ | 新增元素 |
| 删除卡片 | ✅ | 删除元素 |
| 移动卡片 | ✅ | 位置变化 |
| 缩放卡片 | ✅ | 尺寸变化 |
| 创建连线 | ✅ | 连接关系变化 |
| 删除连线 | ✅ | 连接关系变化 |
| 修改卡片内容 | ✅ | 数据变化 |
| 粘贴 | ✅ | 新增元素 |
| 撤销/重做 | ❌ | 本身是恢复操作 |
| 画布平移/缩放 | ❌ | 视图状态，不影响数据 |
| 选中/取消选中 | ❌ | UI 状态 |

### 5.3 快照数据规范

**必须包含的字段：**

```javascript
{
    cards: [
        {
            id: string,      // 卡片 ID
            type: string,    // 卡片类型
            title: string,   // 标题
            left: string,     // 位置（CSS 值，如 '100px'）
            top: string,
            width: string,    // 尺寸（CSS 值）
            height: string,
            bg: string,       // 背景色
            content: string   // 内容（子类扩展）
            // ... 其他子类特定字段
        }
    ],
    connections: [
        {
            start: string,    // 起点卡片 ID
            end: string,      // 终点卡片 ID
            endPort: string   // 终点端口（nullable）
        }
    ],
    canvas: {
        scale: number,
        panX: number,
        panY: number
    }
}
```

## 六、代码风格规范

### 6.1 命名规范

```javascript
// 文件名：kebab-case
undo-redo.js
clipboard.js
card-factory.js

// 类名：PascalCase
class BaseCard {}
class CardFactory {}

// 方法名：camelCase
createElement() {}
serialize() {}

// 常量：UPPER_SNAKE_CASE
const MAX_HISTORY_STEPS = 50;
const BASE64_PLACEHOLDER = '__base64_pending__';

// 私有属性：_前缀（约定）
class MyClass {
    _privateField = null;
    _privateMethod() {}
}

// DOM 元素引用：$前缀或 _el后缀（约定）
this.$element = document.querySelector('.card');
this.element_ = document.querySelector('.card');
```

### 6.2 注释规范

**只写必要的注释，不写显而易见的代码 narration：**

```javascript
// ✅ 正确：说明"为什么"而非"做什么"
// 撤销时需要保存当前状态，用于恢复
UndoRedo.save();

// ❌ 错误：重复代码在做什么
// 调用 UndoRedo.save() 方法
UndoRedo.save();

// ✅ 正确：解释非显而易见的约束
// base64 不进历史记录，只存占位符
// 换成本地路径后（file://），正常存储（体积极小）
if (content.startsWith('data:image')) {
    content = '__base64_pending__';
}

// ❌ 错误：不要在生产代码中留变更历史注释
// ══════════════════════════════════════════════════
// 【重要修改】以下钩子已删除：
// ...
```

### 6.3 错误处理规范

```javascript
// ✅ 正确：使用 console.error + 防御性检查
const instance = CardFactory.getInstance(cardId);
if (!instance) {
    console.error('[Clipboard] 卡片实例丢失:', cardId);
    return;
}

// ❌ 错误：静默失败
if (!instance) return;  // 没有日志

// ✅ 正确：验证必要参数
function create(type, options) {
    if (!type) {
        throw new Error('卡片类型不能为空');
    }
    // ...
}
```

### 6.4 性能规范

```javascript
// ✅ 正确：使用 requestAnimationFrame 进行批量 DOM 操作
let rafId = null;
const onMove = (e) => {
    if (rafId !== null) return;
    rafId = requestAnimationFrame(() => {
        rafId = null;
        // DOM 操作
    });
};

// ✅ 正确：节流频繁调用
ConnectionManager.scheduleUpdate(cardId);  // 内部已实现节流

// ❌ 错误：在循环中直接操作 DOM
cards.forEach(card => {
    card.updateUI();  // 每次都触发重绘
});
```

## 七、模块间依赖规范

### 7.1 加载顺序约束

```
state/*.js        → 先加载（定义全局状态）
core/*.js         → state 之后（依赖 AppState）
services/*.js     → core 之后（可能调用 core）
cards/*.js        → 卡片类定义
cards/CardFactory → 在所有卡片类之后加载
components/*.js   → UI 组件（依赖 core、cards、state）
main.js           → 最后加载（协调各方）
```

### 7.2 依赖方向规则

```
state     ← 被依赖，不依赖其他
core      ← 依赖 state
services  ← 依赖 core、utils
cards     ← 依赖 core、state
components ← 依赖 core、cards、services
main      ← 协调各方
```

**禁止反向依赖：**
- ❌ `cards/` 不应依赖 `components/`
- ❌ `core/` 不应依赖 `components/`
- ❌ `state/` 不应依赖任何模块

### 7.3 跨模块通信规范

**通过事件总线通信：**

```javascript
// 发布
CardEventBus.emit('my-event', { data: 'value' });

// 订阅（在 event-bus-init.js 中集中注册）
CardEventBus.on('my-event', (event) => {
    // 处理
});
```

**通过公开 API 通信：**

```javascript
// 调用
Clipboard.copy();

// 不直接访问内部
// ❌ CardFactory._instances['card-123'] = null;
```

## 十、常见问题 FAQ

**Q: 应该在什么时候创建新文件，而不是在现有文件中添加？**

A: 当新功能符合以下任一条件时创建新文件：
- 职责独立，可以单独测试
- 与现有文件没有紧密耦合
- 预计会持续扩展

**Q: 可以在 cards/ 目录下添加非卡片类吗？**

A: 不可以。`cards/` 目录专门用于卡片系统。如有通用领域逻辑，考虑放在 `core/` 或 `utils/`。

**Q: 什么时候使用继承，什么时候使用组合？**

A:
- 继承：卡片类型有共同的行为模式（如拖拽、缩放、端口）→ 使用 `extends BaseCard`
- 组合：一个功能由多个独立部分组成 → 使用对象组合

**Q: 调试代码可以保留在生产代码中吗？**

A: 可以，但需要：
- 使用统一的日志函数（如 `console.warn` 而非 `console.log`）
- 标注这是调试代码
- 考虑使用 `DEBUG` 常量控制开关

```javascript
const DEBUG = false;
function logPerformance(label, duration) {
    if (DEBUG && duration > 16) {
        console.warn(`[Performance] ${label}: ${duration.toFixed(1)}ms`);
    }
}
```
