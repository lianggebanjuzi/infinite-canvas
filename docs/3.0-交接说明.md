## 产品目标

把 Infinite Canvas 从“可配置的 AI 生成节点画布”重构为“**以图片为中心的连续创作画布**”。

用户面对的主线应当是：

```text
素材 / 灵感图 → 生成或编辑 → 结果紧贴原图形成版本链 → 选结果继续创作 → 整理成方案
```

而不是：

```text
先创建配置节点 → 填一排通用参数 → 拉线 → 执行
```

参考体验：<https://github.com/Valiera00/SPITE>。

SPITE 值得借鉴的是图片主导的画布、低干扰参数、结果复用、资产组织、场景化整理和 Flow（线性创作）入口。它偏影视前期；3.0 **不应**因此收窄成分镜工具。

## 授权边界

## 3.0 的体验原则

### 1. 图片优先

选中一张图片后，显示与图片语义有关的动作，例如继续创作、扩图、局部修改、放大、换背景、多角度、下载。不要首先展示模型、分辨率、数量等配置芯片。

### 2. 参数按任务出现

- 扩图：目标比例、原图位置、原图缩放是主参数。
- 局部修改：修改区域、批注/蒙版、修改指令是主参数。
- 生图：提示词、参考图、比例才是主参数。
- 高级模型、分辨率、张数等进入“更多设置”，不要抢占首屏。

### 3. 结果是版本链，不是杂乱节点

一次操作产生的结果应当靠近源图并可清楚看出父子关系；用户可以浏览候选、设为主版本、从任何版本继续。

### 4. Flow 是简化入口，不是第二套数据模型

可以设计一个线性的“继续创作”体验，但它生成的图片、参数、历史和关系必须和画布共用同一套节点与数据模型。

### 5. 画布用于思考与整理

连接线仅在表达来源、参考、版本关系时出现。不要要求普通用户先理解 DAG 才能生成图片。

## 建议实施顺序

不要一次性大改全部节点。每一阶段完成后运行构建与相应回归，再进入下一阶段。

### Phase 1：重新定义图片卡片与版本关系

- 审核图片卡片、选中态、图片操作条、右键菜单、结果节点的现状。
- 明确区分“参考关系”“操作步骤”“结果版本”三种关系的视觉表达。
- 让从图片发起的操作有稳定、可预期的结果落点。
- 不改变现有项目文件兼容格式，除非先写迁移方案并征得确认。

验收：用户不看连线也能看懂“这张图由哪张图生成、下一步可以做什么”。

### Phase 2：收敛操作面板

- 把图片操作收敛成任务型入口；扩图面板作为第一个样例。
- 清理扩图状态下无意义的通用模型/比例/数量芯片。
- 为任务型设置提供明确摘要，例如“扩图画布：16:9，原图居中”。
- 保留高级设置，但默认折叠。

验收：用户点击扩图后，在不猜测的情况下能找到并调整比例、原图位置和缩放。

### Phase 3：结果链与历史

- 将单次操作的候选结果组织为可浏览的版本组。
- 支持从任意结果复用当前参数、重新编辑、重跑。
- 历史记录应能跳回对应节点/版本，且显示实际生效参数。

验收：运行、失败、修改、重跑、选定结果、继续创作的全过程不丢上下文。

### Phase 4：Flow 原型（需先确认）

只在前三阶段验证后再做。Flow 不另建持久化体系；它只是画布节点的线性视图或快捷入口。

## 这轮明确不做

- 不直接复制 SPITE 代码或界面。
- 不把产品改成影视分镜专用工具。
- 不引入 ComfyUI 才能使用的复杂节点图。
- 不在未经确认时重做后端、账户、计费、云同步或整个持久化格式。
- 不删除 2.1 的扩图、历史、批次与已有图片生成能力。

## 工作方式

1. 每次只推进一个 Phase 的小切片，先说明变更范围与验收点。
2. 改代码前先检查 `git status`，不要覆盖用户已有修改。
3. 每个行为改动至少运行 `npm run build`；涉及扩图必须再跑扩图 smoke 回归。
4. 做出可见交互后，优先让用户在应用里确认体验，再继续扩大范围。
5. 任何会改变项目兼容格式、数据结构或移除现有能力的决定，都必须先询问用户。
