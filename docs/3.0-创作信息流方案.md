# Infinite Canvas 3.0：创作信息流方案

## 这份文档在解决什么

3.0 不应继续把功能堆在画布卡片上，也不应以“扩图”为入口重做产品。

它要解决的是：创作做久了以后，图片、尝试过程、提示词和分支不会散掉；用户能从任意一张图继续做，也能回看当时为什么得到这张图。

参考项目 SPITE 的价值不在于它的影视界面，而在于它把**图片、一次创作、画布摆放**分成了三件事。3.0 借鉴这个信息流，保持自己的图像创作定位和视觉风格；不复制其界面、源码或影视分镜功能。

## 一句话定义

**所有图片都属于项目；每一次创作都留下过程；画布和时间线只是在不同角度使用同一批内容。**

## 用户真正看到的三样东西

### 1. 项目作品库：所有图片的“总相册”

导入的参考图、生成结果、编辑结果都在这里。每张图只有一份，不会因为被拖到画布、查看历史或继续创作而变成多个副本。

图片可以有来源信息，例如“手动导入”“由哪一次创作产生”“是否被用作参考图”。

### 2. 创作记录：一次操作就是一张“订单”

例如：

```text
输入：参考图 A
想法：把它变成下雨的夜景
设置：所选模型、尺寸、其他参数
结果：图片 B、图片 C
```

这不是一个孤立的画布卡片，而是一条可回看的创作记录。以后点开 B，就能知道它来自 A、当时写了什么、还能以相同设置再做一次或修改后继续做。

### 3. 两种观看方式：画布与时间线

它们使用的是同一张图和同一条创作记录，只是看法不同：

```text
时间线（顺着做）
A → 创作 1 → B → 创作 2 → C

画布（自由组织）
       → B → C
A ────┤
       → D
```

- **时间线**适合你像现在一样，一步接一步地说、一步接一步地做。
- **画布**适合把几个版本并排比较，或从同一张图开出多个方向。

它们不是两套资料。时间线里出现的 B，放到画布后仍然是同一个 B。

## 最重要的行为规则

### 从一张图继续做

选中图片 B，选择“继续创作”，系统自动把 B 带入新的创作记录。你只需要补充下一句想法或修改设置。

```text
A → “雨夜街道” → B → “增加霓虹和人群” → C
```

### 从同一张图尝试不同方向

同一张 B 可以分别产生 C 和 D。两条路都保留，不要求用户在开始前做“覆盖”或“二选一”。

```text
             → “更电影感” → C
B ──────────┤
             → “更写实”   → D
```

### 从画布移走，不等于删除作品

把 B 从画布移走，只是取消摆放；B 仍在项目作品库和创作记录中。只有用户明确删除作品，才进入真正删除流程。

### 结果可以直接复用

任何历史结果都可以：

- 重新放到画布；
- 当成下一次创作的参考图；
- 查看其来源和当时的设置；
- 基于它建立新的分支。

## 背后的信息关系

```text
项目
├─ 作品库
│  ├─ 图片 A（导入）
│  ├─ 图片 B（创作 1 的结果）
│  └─ 图片 C（创作 2 的结果）
├─ 创作记录
│  ├─ 创作 1：A + “雨夜街道” → B
│  └─ 创作 2：B + “增加霓虹” → C
└─ 视图
   ├─ 时间线：按创作先后串起来
   └─ 画布：把作品自由摆放、连接、比较
```

所以“图”“一次创作”“图在画布上的位置”是三种不同的信息：

| 信息 | 它回答的问题 |
| --- | --- |
| 图片 | 这张作品是什么？ |
| 创作记录 | 它是怎么来的？ |
| 画布摆放 | 我现在想怎样看、比较和整理它？ |

## 与现在做法的差别

现在更像是：一张卡片同时装着图片、提示词、模型、结果、位置和操作。卡片一多，资料就跟着散，复用和回溯也会变难。

3.0 应改为：卡片或条目只是“指向一张作品 / 一次创作”的入口。核心资料在项目里统一保存；画布只是组织方式，不再是唯一的资料容器。

## 第一阶段应该先做什么

不急着增添具体图像功能，先让一个最小闭环成立：

1. 导入一张图，进入项目作品库；
2. 以它为输入，提交一次创作；
3. 结果进入作品库，并保存与输入、提示词、模型的关系；
4. 同一个结果既能在线性时间线里看到，也能拖到画布；
5. 从画布移走后，作品和创作记录仍然存在；
6. 点击任意结果，可以继续创作或回看来源。

扩图只是将来可挂在“创作记录”上的一种操作类型，不是 3.0 的信息架构中心，也不应抢占第一阶段。

## 目前明确不做的事

- 不照搬 SPITE 的影视项目、场景、镜头等产品定位；
- 不复制 SPITE 的界面、代码或素材；
- 不为了看起来相似而先堆叠侧栏、卡片和按钮；
- 不在未确认前重做账户、云端同步或后端服务；
- 不把既有的扩图能力删掉或强行改成交互主入口。

## 判断 3.0 是否做对了

用户应能自然地完成这句话：

> “我从这张图开始，试了两个方向；我知道每个结果怎么来的；我可以把其中一个继续做，也可以把它们并排放到画布上比较。”

如果这件事不顺，那么即使界面再像参考项目，也还没有达到 3.0 的目标。

## 参考边界

SPITE 被用作产品信息流研究对象。其公开仓库采用 AGPL 许可证，因此本项目只吸收抽象的产品原则，独立实现自己的数据、交互和界面。
