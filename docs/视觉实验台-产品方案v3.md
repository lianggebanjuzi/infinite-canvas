## 一、一句话定义

> 为园艺电商视觉设计师打造的本地视觉实验台：以「场景」和「植物/花材」为核心资产，用无限画布做实验桌面，所有 AI 生成结果都有档案，好的结果被采纳、锁定、进库、复用。

---

## 二、为什么不是固定流水线

当前工作流还不确定，主要有三种模式：

| 模式 | 过程 |
|---|---|
| A | AI 跑图 → 根据图重搭场景 → 渲染 |
| B | 搭场景 → 白模固定构图/透视 → AI 换花材/风格/季节 |
| C | AI 生成各种花 → 挑选合适花材 → 放进场景验证 |

这三种模式不是三个软件，而是同一件事的不同阶段：

```
探索 → 生成 → 比较 → 选择 → 固定 → 复用
```

所以产品不做死流水线，而是做一个**可自由组合、可积累、可复现**的实验台。工作流在真实使用中长出来，之后才固化成模板。

---

## 三、核心原则

1. **场景是锚点**：白模/参考图节点锁定后，只作为参考图来源，不参与重跑。
2. **每张图都有档案**：prompt、模型、比例、分辨率、参考图指纹、时间、父节点。
3. **好结果立刻固定**：采纳/锁定后不被重跑顶掉。
4. **资产库优先于画布**：花材库、场景库、成图库是长期资产，画布只是桌面。
5. **本地优先**：数据在自己电脑上，离线可用，导出开放。
6. **不求像素级复现**：seed 留口子，但不依赖；先做参数级复现。
7. **不做的红线**：不做账号协作、不做移动端、不做 ComfyUI 本地引擎、不做通用白板。

## 四、核心对象模型

### 4.1 五大对象

```
Project
  ├─ Node[]       卡片：一次实验或一个资产在画布上的存在
  ├─ Edge[]       连线：数据/参考图来源关系
  ├─ Asset[]      资产：花材 / 场景 / 成图 / 提示词
  ├─ Run[]        执行记录：每次生成产出了什么
  └─ Snapshot[]   版本快照：时间机器
```

### 4.2 节点类型（注册式）

| 类型 | 作用 | 状态 |
|---|---|---|
| `scene` | 白模场景 / 参考图，构图锚点 | 锁定后不重跑 |
| `asset` | 植物 / 花材 / 产品图 | 可拖入，可作参考图 |
| `image-gen` | AI 生图 / 改图 / 换风格 | 生成变体 |
| `text-gen` | AI 文本：改 prompt、反推图、打标签 | 辅助 |
| `outpaint` | 扩图 | 复用现有逻辑 |
| 后期 | 生成复现 JSON / 3D 复现 / 场景合成 | 按真实需求长出来 |

### 4.3 资产字段（以植物为例）

```
{
  id, type: 'plant',
  name: '大花绣球',
  tags: ['半阴', '6-9月', '蓝粉紫', '容器'],
  height: '50-150cm',
  light: '半阴',
  season: '6-9月',
  style: ['英式花园', '庭院角落'],
  companions: ['玉簪', '蕨类'],
  usage: ['门廊', '花境', '盆栽'],
  images: [...],
  prompt: '绣球花，球状花序，柔和饱满',
  source: 'ai' | 'photo' | 'project'
}
```

行业差异只发生在 `Asset` 字段和 `Node` 类型上，骨架不变。

### 4.4 生成档案（Trace）

每张产出图都带：

```
{
  prompt,
  model,
  aspectRatio,
  resolution,
  count,
  refImageHashes: [],
  seed: null,
  createdAt,
  parentId,
  outputType: 'txt2img' | 'img2img' | 'outpaint'
}
```

作用：追溯、复现、批量对比、沉淀成模板。

## 五、界面结构

```
┌──────────────────────────────────────────────────────┐
│ 顶栏：项目名 · 保存状态 · 新建 · 主题                    │
├────────────┬─────────────────────────────────────────┤
│ 左侧资产库  │  画布                                    │
│            │   · 场景锚点卡                            │
│ [场景]      │   · 花材卡                               │
│ [花材]      │   · AI 变体卡                            │
│ [成图]      │   · 连线（参考图来源）                     │
│ [提示词模板] │   · 选中卡 → 下方浮出指令面板              │
│            │                                         │
├────────────┴─────────────────────────────────────────┤
│ 底部：打开 · 保存 · 设置 · 运行选中 · 对比(n)            │
└──────────────────────────────────────────────────────┘
```

### 指令面板

- 输入框：prompt / 命令
- 参数 chip：模型 / 比例 / 分辨率 / 张数
- 按钮：发送 · 档案 · 采纳/锁定 · 加入对比 · 复现

### 对比面板

- 2 / 4 / 8 宫格并排查看
- 在对比面板内直接采纳
- 淘汰的留在图库，不污染主链

## 六、三种工作流如何映射

### 模式 A：AI 跑图 → 重搭场景 → 渲染

```
[场景参考图] → [AI 生成场景方案] → 多变体 → 选一张 → 标记「按此搭场景」→ 导出
```

### 模式 B：白模固定场景 → AI 换花材

```
[白模场景] ─┬→ [AI 换花材 A] → 变体1 变体2 变体3
            ├→ [AI 换风格 B] → 变体1 变体2
            └→ [AI 加花 C]   → 变体1 变体2
```

白模节点是锚点，永远只作参考图来源。

### 模式 C：AI 生成各种花 → 挑选

```
[提示词模板：花境植物] → 批量生成 8 张
      → 逐张看 → 好的采纳 → 存入花材库
                          → 再拖进 [白模场景] 试配
```

## 九、实施路线

### 第 0 步：收口（半天）
- `npm run build`
- 跑 smoke 测试
- 提交干净一版

### 第 1 步：信任层（1-2 周）
- 原子保存：先写 `.tmp` 再 `os.replace`
- 自动保存：60 秒 + 失焦
- 关闭保护：未保存弹窗
- 打开项目前检查 dirty
- 最小撤销/重做
- 历史图库持久化

### 第 2 步：资产与档案层（2-3 周）
- 花材库 / 场景库 / 成图库
- 资产标签、搜索、拖入画布
- 每张产出图写 `trace`
- 采纳 / 锁定
- 复现按钮
- 提示词模板 UI

### 第 3 步：实验与评估层（3-4 周）
- 批量变体 + 并排对比
- 对比面板内采纳
- 好图一键入库
- 白模场景锚点节点

### 第 4 步：模板与 Agent（长期）
- 真实项目跑 10-20 个后，把反复出现的流程固化成模板
- Agent 指挥画布
- 生成复现 JSON / 3D 复现 / 场景合成

## 十、验收标准

1. 打开软件 10 秒内能接着昨天的项目继续。
2. 误关窗口不丢工作；崩溃最多丢一分钟。
3. 每张 AI 图都能查到它怎么来的。
4. 好的结果能被采纳锁定，不被重跑顶掉。
5. 花材/场景资产能积累、搜索、拖入复用。
6. 每周主动打开次数可统计（usage.log）。

## 十二、原型阅读指南

打开 `prototypes/ui-v3-concept.html` 后，按这个顺序试：

1. 点左侧「花材」资产，看它如何进入画布；
2. 点选 AI 变体卡，看指令面板；
3. 点「档案」看 trace；
4. 点「加入对比」，再选另一张，点底部「对比」；
5. 在对比面板里「采纳」一张；
6. 点「复现」，看参数如何回填；
7. 选中卡片按 Delete 删除。

原型中的 emoji 和占位图会在正式版替换为统一 SVG 和真实图片。
