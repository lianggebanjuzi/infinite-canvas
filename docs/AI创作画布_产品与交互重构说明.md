# AI 创作无限画布：产品与交互重构说明

## 1. 目的

本文件供开发 AI 或开发者直接实施。目标是把现有 AI 创作画布收敛为稳定、直观、可扩展的图片创作工作台，而不是继续把功能和表单堆进节点卡片。

可参考 [basketikun/infinite-canvas](https://github.com/basketikun/infinite-canvas) 的产品思路：原始内容和 AI 产出分离、生成结果可追溯、画布用于编排创作关系。不要整套搬运外部项目；若直接复用较大段 MIT 代码，必须保留版权声明。

## 2. 产品核心原则

### 2.1 画布展示创作关系，不展示底层数据

用户最想在画布上直观看到的是：

```text
哪张图  →  经由哪一步创作  →  变成哪张图 / 哪一组图
```

画布第一视觉应该是图片、素材、文字摘要及它们之间的连线。用户应能一眼看明白某张结果图来自哪张参考图、哪段文案或哪个批次。

画布上不应展示完整提示词、JSON、端口原始数据、模型参数、全部任务状态或错误堆栈。这些仅在用户点击节点、连线或批次后，在侧栏/底部面板/结果查看器中按需查看。

允许在画布上显示的最少信息：

- 图片：清晰缩略图、轻量状态点、加载动画、结果数量角标（如 `5/15`）。
- 文本：一两行摘要或“提示词/文案”标签。
- 文本拆分：`已拆分 15 条`，不展开 15 个输入框。
- 连线：明确的方向与来源关系；选中时再显示“参考图”“反推结果”“拆分提示词”等说明。

### 2.2 分层，而非把所有功能压进画布

| 区域 | 只负责什么 | 不应负责什么 |
| --- | --- | --- |
| 画布 | 创建、移动、连接、选择节点；以图片与连线表达创作演化 | 长文本、完整参数、任务日志 |
| 右侧属性编辑器 | 编辑选中节点的完整文本、拆分符、模型与参数 | 批量任务列表、画布排版 |
| 底部任务面板 | 显示批次和单个任务的排队、生成、成功、失败、重试 | 编辑提示词 |
| 结果查看器（抽屉/弹层） | 看大图、切换多张结果、下载、继续反推/编辑 | 节点配置 |

### 2.3 系统级保护规则

1. 用户手动输入的文本和参数，在失焦、切换节点、运行成功、失败、取消、重试后都不得自动清空。
2. 上游输入只作为运行时来源，不能静默覆盖用户本地编辑的字段。
3. 节点结果和历史批次不因重跑或下游失败而丢失；新运行只生成新的批次记录。
4. UI 前置校验、卡片提示与实际执行必须使用同一份数据解析逻辑。

## 3. 主流程

```text
图片/素材
  → 文本节点（反推、改写、整理）
  → 文本拆分节点（提示词列表）
  → 图片生成节点（一个批次）
  → 结果图片组（浏览、选择、继续创作）
```

也应支持：

```text
文本节点 → 图片生成节点
图片节点 → 文本节点（反推）
图片节点 → 图片生成节点（图生图）
```

## 4. 节点和连线的数据契约

连线必须有明确的数据类型，不能只用“有没有上游连线”判断。

| 类型 | 含义 | 典型来源 | 典型去向 |
| --- | --- | --- | --- |
| `Image` | 单张图片，含尺寸和来源信息 | 素材、图片生成 | 反推、图生图、参考图 |
| `ImageList` | 同一批次的一组图片 | 批量图片生成 | 结果查看器、导出、选择 |
| `Text` | 一段完整文本 | 文本节点、反推结果 | 改写、图片生成、拆分 |
| `TextList` | 多条独立提示词 | 文本拆分 | 批量图片生成 |
| `GenerationConfig` | 模型、比例、质量等生成参数 | 图片生成节点 | 任务执行器 |

### 4.1 素材/图片节点

- 输出 `Image`。
- 画布上以缩略图为主体；有图片时，可拖线用于反推或图生图。
- 不承担长提示词编辑与任务日志。

### 4.2 文本节点

- 输入：可选 `Image` 或 `Text`；输出 `Text`。
- 图片上游存在时可执行反推；文本上游存在时可改写、扩写、整理。
- 画布只显示文本摘要；完整编辑在右侧属性编辑器进行。
- AI 改写默认向右创建连接的“结果文本节点”，保留原文；只有用户主动选择“覆盖当前文本”才覆盖当前节点。

### 4.3 文本拆分节点

- 输入：可选 `Text`；输出 `TextList`。
- 参数：`delimiter`（分隔符）、手动 `segments`（槽位）。
- 有有效上游文本时：按分隔符拆分，自动计算段数，去掉分隔符本身、空白项；不把上游内容静默写进手动槽位。
- 没有上游文本时：使用手动槽位。
- 画布显示 `文本拆分 · 15 条`；点击后才显示分隔符、完整结果和编辑入口。
- 允许用户选择“复制到手动编辑”，但不能默认覆盖手工内容。

### 4.4 图片生成节点

- 输入：`Text`、`TextList`、可选 `Image`/`ImageList` 参考图。
- 输出：单图时为 `Image`，批量时为 `ImageList`。
- 无上游文本：本地 `prompt` 必填，按本地 `count` 生成。
- 接收 `Text`：上游文本作为主提示词；本地只能是可选“追加修饰词”，不可暗中覆盖上游。
- 接收 `TextList`：每条文本创建一个任务；隐藏/禁用本地张数选择，总数由 `TextList.length` 决定。
- 接收 `TextList` 时，所有结果归属于同一图片生成节点和同一个批次；画布只显示当前图和 `成功数/总数`，点击后可切换全部图片。

## 5. 画布交互规范

### 5.1 节点视觉

1. 每张卡片有最大高度。长图使用 `contain` 或裁切缩略图，不能顶穿画布。
2. 图片节点以图片为主，信息标签应极少；文本节点只显示摘要；拆分节点只显示段数。
3. 状态使用低干扰视觉：颜色点、角标、细边框、加载流光。不要把 HTTP 返回、错误长文或参数表直接放在卡片里。
4. 批量结果不在画布上展开 15 张卡片，除非用户显式选择“展开为画布节点”。默认保持一个结果组节点。

### 5.2 连线视觉

1. 连线方向必须清楚：左到右或上到下保持一致，箭头或端口方向明确。
2. 连接图片时，用户应一眼知道哪张是参考图、哪张是结果图；可通过柔和的线色/小图标区分“图片参考”“反推文本”“文本生图”。
3. 选中连线后在侧栏展示数据来源和类型；未选中时不要用文字污染画布。
4. 拖线时只高亮兼容端口，不兼容的连接应拒绝并简短说明。
5. 改变上游文本或拆分符后，下游标为“待重新生成/已过期”，但不清空旧结果。

### 5.3 基础操作

- 单击：选中节点，右侧打开属性。
- 双击文本摘要：进入文本编辑。
- 点击运行按钮或快捷键：运行选中节点。
- 点击图片：打开结果查看器，不在画布内展开大图。
- 点击空白处：取消选择；未保存文本必须已即时保存为草稿或可靠持久化。
- 优先保证平移、缩放、框选、多选、复制、粘贴、删除、撤销、重做、拖拽文件创建素材节点、画布导入导出。

## 6. 上游数据和本地编辑规则

所有节点统一执行以下规则：

1. 上游数据是运行时输入，不是允许直接覆盖本地表单值的命令。
2. 本地字段只能由用户编辑、导入或用户确认“应用上游内容”时改变。
3. 共享解析函数。例如 `getTextSplitSegments(nodeId)` 必须同时被拆分 UI、图片节点 `canRun`、图片批量执行器调用。
4. 有有效上游 `TextList` 时，图片节点绝不能报“请输入提示词”。
5. 一旦上游有效内容改变，下游标过期；历史输入和历史结果仍保留。

## 7. 批量生图必须使用任务队列

### 7.1 禁止的实现

禁止直接对 15 条提示词使用无上限 `Promise.allSettled` 同时创建 15 个远端请求。它会造成第三方 API 限流、服务端队列饱和、网络超时或任务创建失败；若只返回 5 张图，用户还无法知道另外 10 条的状态。

### 7.2 数据模型

```ts
type JobStatus = 'queued' | 'creating' | 'running' | 'succeeded' | 'failed' | 'cancelled';

interface GenerationJob {
  id: string;
  batchId: string;
  index: number;
  prompt: string;
  status: JobStatus;
  remoteTaskId?: string;
  image?: { url: string; originalPath?: string; originalUrl?: string; width?: number; height?: number };
  error?: string;
  attempts: number;
  createdAt: number;
  startedAt?: number;
  finishedAt?: number;
}

interface GenerationBatch {
  id: string;
  nodeId: string;
  source: 'manual-count' | 'text-split';
  total: number;
  concurrency: number;
  status: 'queued' | 'running' | 'completed' | 'partial-failed' | 'failed' | 'cancelled';
  jobs: GenerationJob[];
  createdAt: number;
  finishedAt?: number;
}
```

### 7.3 执行方式

```text
TextList（15 条）
  → 创建 1 个 Batch（total=15）
  → 创建 15 个 Job（全部 queued）
  → 队列同时最多执行 2~3 个 Job
  → 每条独立创建远端任务、轮询、保存结果或错误
  → 每次状态改变，刷新画布的数量角标与底部面板
  → 全部结束后标记 completed / partial-failed / failed
```

要求：

1. 默认并发为 `2`，可配置 `1~3`；绝不无限并发。
2. 每个 Job 独立保存错误原因，不能只保存一个 `lastError`。
3. 成功图不能因其他任务失败而丢失。
4. 失败项可“重试此条”或“重试全部失败项”。
5. 结束时明确显示 `成功 5/15，失败 10`；用户可逐项查看原提示词、错误与重试按钮。
6. 任务状态和结果至少在当前项目会话内持久化；刷新后能恢复已知结果，或明确标记状态未知。

## 8. 任务面板与结果查看器

### 8.1 底部任务面板

- 展示当前批次概况：总数、排队、运行、成功、失败。
- 展示 `#1 ~ #15` 任务列表；成功项显示小缩略图，失败项显示简短错误和重试。
- 任务细节默认折叠；用户需要排错时才打开，不污染画布。

### 8.2 图片结果查看器

- 画布点击图片或结果组打开。
- 支持上一张/下一张、缩略图列表、`第 3/15 张` 指示。
- 单张详情中显示该图的提示词、模型、尺寸、参考图、批次号、生成时间。
- 操作包括下载、复制提示词、以此图反推、作为参考图继续生成、单项重试。

## 9. 可追溯数据

每张 AI 生成图片都应记录可复现信息：

```ts
interface GenerationTrace {
  prompt: string;
  model: string;
  aspectRatio?: string;
  resolution?: string;
  referenceImageIds?: string[];
  sourceNodeIds?: string[];
  batchId?: string;
  jobId?: string;
  createdAt: number;
}
```

从任意成功图应可追溯它来自哪条拆分文本、哪张参考图和哪一次批次；从任意失败任务应能看见原提示词与明确错误。图片缩略图、原始 URL 和本地原图路径应各自有明确职责，加载失败不能静默白屏。

## 10. 实施顺序

### 阶段 A：数据流与输入保护

1. 为节点和端口补齐输入/输出类型。
2. 统一上游数据解析函数，供 UI、校验、执行共用。
3. 修复所有会丢失输入内容的交互。
4. 确保文本拆分 → 图片生成不再重复要求填写提示词。

### 阶段 B：批次队列

1. 引入 `GenerationBatch` 和 `GenerationJob`。
2. 用有限并发队列替换全量并发请求。
3. 实现单条状态、错误、重试和任务面板。
4. 把图片节点改为结果组的紧凑预览。

### 阶段 C：画布与细节分层

1. 卡片高度上限、图片缩略图、文本摘要、状态角标。
2. 建立右侧属性编辑器，移出长文本、拆分槽位和参数。
3. 建立结果查看器，移出大图和批量图片浏览。
4. 优化连线，让图片来源和演化关系优先可读。

### 阶段 D：基础创作体验

完善多选、复制粘贴、撤销重做、自动布局、导入导出，并为拆分、批量、反推和图生图添加可复现测试。

## 11. 验收标准

1. 一眼能看出任意结果图片来自哪张图/哪个创作节点；但画布上看不到冗长提示词、参数、错误日志或数据结构。
2. 文本拆分出 15 段时，画布只显示 `已拆分 15 条`；点击后才显示完整段落。
3. 文本拆分连接图片生成后，图片节点不要求额外输入提示词，本地张数不可编辑，生成总数为 15。
4. 15 条提示词产生 15 个可见 Job，不会静默丢失；若成功 5 条失败 10 条，用户可以分别看到 5 张成功图和 10 条失败原因。
5. 长文本、长图、多图都不会把画布卡片撑出可用高度。
6. 文本输入在失焦、切换节点、成功、失败、取消、重跑后仍保留。
7. 用户可以点击任意图片查看其提示词、模型、来源与批次，并继续反推或再生图。
