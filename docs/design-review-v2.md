## 一、P0 精修项（阻断定稿，必须先改）

### P0-1 节点信息无处呈现 —— 补上「卡片下沿信息条」

- **现状**：卡片只有大图 + 左上标签（状态点 + 节点名）。决策明确要求的「关键词、模型名、比例、分辨率」四项信息在 UI 上没有位置。
- **改成什么**：卡片图片下沿加一条悬浮信息条（与标签同一视觉语言：深色半透明底 + 8px 模糊），单行展示 `关键词截断 · 模型名 · 3:4 · 2K`，默认仅显示模型+比例+分辨率（11px，`--fg` 反白色），hover 或选中时展开显示完整关键词。超长关键词用省略号截断，title 悬浮显示全文。
- **为什么**：这是已拍板决策的硬性条目，不是加分项。用户改关键词→下游标脏是核心交互循环，关键词不可见 = 用户无法一眼确认"这张卡是用什么词跑出来的"，脏标记的信任基础就没了。

### P0-2 硬编码色值穿透主题系统 —— 全部 Token 化

- **现状**：以下处绕开了 CSS 变量，深色主题下不会切换或产生错误颜色：
  1. `.pcard:hover` 阴影 `rgba(120,100,80,...)` 硬编码（第 137 行）——深色模式下 hover 卡片会泛出暖棕色光，暖棕黑主题里极其突兀；
  2. SVG `flowGrad` 两个 `stop-color="#7C9A72"` 硬编码（第 350-352 行）——深色下流光仍是浅色绿，与深色 accent `#93AC87` 脱节；
  3. `.link-path.flowing` 的光晕 `drop-shadow(rgba(124,154,114,.6))` 硬编码（第 120 行）；
  4. toast 失败图标 `stroke="#D97B6C"` 硬编码（第 590 行）；
  5. `.pcard-tag` / `.pcard-act` 底色 `rgba(30,28,25,.55)` 硬编码（可接受，但应抽为 `--overlay-dim` 统一管理）。
- **改成什么**：全部迁入 Token（见 `design-tokens-draft.css`）：阴影色抽 `--shadow-rgb` 通道变量，浅色 `120,100,80` / 深色 `0,0,0`；SVG stop-color 直接用 `stop-color="var(--st-run)"`（SVG 属性支持 CSS 变量）；光晕抽 `--link-flow-glow`。
- **为什么**：双主题是用户拍板项，硬编码 = 主题切换半成品。这类穿透会随开发复制扩散，原型阶段不收口，代码里就收不住了。

### P0-3 状态点「运行中」与「完成」一瞥难分辨

- **现状**：`--st-run: #7C9A72` 与 `--st-done: #5FA878` 明度几乎相同（L≈55% vs 52%），都是中明度灰绿。7px 小圆点上，脉冲动画一旦没被注意到，运行中和完成无法区分。
- **改成什么**：拉开明度与饱和度两轴——运行中用 accent 亮绿 `#7C9A72`（脉冲），完成用**深绿 `#4A7C59`**（深、静、落定感）；深色主题对应 `#93AC87` / `#63A878`。同时脉冲周期从 1.2s 放缓到 1.6s（呼吸感，不催促）。
- **为什么**：状态点是「无文字日志」决策下唯一的运行反馈载体，五态必须一瞥可辨。灰绿系配色天生相邻，必须主动拉开差距。脉冲放缓是温馨园艺的气质要求——绿植生长不着急。

### P0-4 「标记」「风格」标签页是空壳

- **现状**：三个标签页切换只改 active 样式，内容区永远是参考图缩略 + 输入框。「标记」「风格」点了没有任何对应内容，用户会以为坏了。
- **改成什么**：二选一——
  - 方案 A（推荐，第一版）：点击后内容区切换为最小可用内容：「标记」页显示圈选/涂抹工具的一行说明 + 标记缩略列表位；「风格」页显示预设风格 chip 组（如：北欧 / 侘寂 / 田园 / 极简，点击填入输入框）。
  - 方案 B（更省）：第一版只保留「参考」单页，其余两个标签先不上，避免空头支票。
- **为什么**：空壳交互比没有交互更伤信任。第一版只做 2 步闭环，标签页应与能力对齐，不做超前承诺。

## 二、P1 精修项（「还不够温馨园艺」的气质欠账）

### P1-1 字体无性格 —— 引入 display 字体定温度

- **现状**：全局 `-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"` 系统栈直出，没有任何品牌气质——这是 AI 模板味的典型来源之一。
- **改成什么**：双字体策略——`--font-display: "Nunito", "PingFang SC", ...`（圆润、有机、有园艺温度，字重 700）用于 logo、标签页标题、侧栏标题、卡片标签；`--font-body` 保持系统栈（正文可读性优先）。Nunito 随应用本地打包（pywebview 离线场景，不走 Google Fonts CDN）。数字类信息（比例、分辨率、参数 chip）用 `--font-mono`（JetBrains Mono）等宽对齐。
- **为什么**：温馨园艺风的「温度」50% 来自字体气质。正文保持系统栈是产品型寄存器的克制；display 字体是品牌指纹。Nunito 是有机自然风的稳妥选择，且未在反射拒绝列表内。

### P1-2 圆角语言混乱 —— 收敛为 5 级阶梯

- **现状**：全原型 8 种圆角混用：卡片 16 / 指令面板 18 / 操作条 13 / 缩略图 10 / chip 9 / 标签 8 / 按钮 8 / 参考图 9。无规律可循。
- **改成什么**：5 级阶梯，按「容器越大、圆角越大」：
  - `--radius-sm: 8px` — 标签、徽章、输入框、icon 按钮
  - `--radius-md: 12px` — 操作条、chip、历史缩略图、参考图
  - `--radius-lg: 16px` — 图片卡片
  - `--radius-xl: 20px` — 指令面板、模态框
  - `--radius-full: 9999px` — 发送钮、状态点、连接端口
- **为什么**：「大圆角」是拍板风格，但大圆角不等于随机圆角。阶梯统一后，用户潜意识里能读出元素层级：小而硬、大而柔。

### P1-3 阴影质感 —— 阴影色 Token 化 + 柔化

- **现状**：暖阴影方向正确（`rgba(120,100,80)` 带棕色调），但 hover 态硬编码（见 P0-2），且悬浮条阴影略重，温馨感应更「晒在布上的光」而非「浮在空中的板」。
- **改成什么**：抽 `--shadow-rgb` 通道变量统一换主题；卡片静态阴影略降不透明度、加大模糊半径（`0 2px 8px /.05, 0 12px 36px /.07`）；悬浮条阴影保持现有强度（浮层需要明确层级）。
- **为什么**：暖阴影是温馨园艺与冷色技术风的分水岭，必须全场景一致，不能一半暖一半黑。

### P1-4 生成完成没有「收获感」

- **现状**：运行结束 = 状态点变色 + toast 一行字。图片从模糊态直接跳变清晰，无过渡（`.ph` 的 `transition: filter .5s` 其实写了，但 run→done 切换时 blur 移除的 0.5s 过渡被 toast 抢戏，感知弱）。
- **改成什么**：完成瞬间加一个 settle 微动画：图片从 `blur(6px) scale(1.02)` 过渡到 `blur(0) scale(1)`，时长 400ms，`cubic-bezier(.2,0,.2,1)`——像显影落定。toast 保留但文案具体化（「北欧风场景 已生成」而非「生成完成」）。
- **为什么**：这是用户每周要重复几十次的核心时刻，「图出来了」的满足感就是这个工具的情绪价值本体。动效在服务内容（显影），不是装饰，符合功能性动效原则。

### P1-5 失败态只靠颜色传达 —— 叠加形状通道

- **现状**：失败 = 状态点变红，唯一信号是颜色。红绿色弱用户（男性约 8%）无法区分红/绿/橙三个状态点。
- **改成什么**：失败态在状态点旁叠加 12px 警告图标（SVG 描边三角形感叹号），或状态点本身改为带 `!` 的圆形；同时所有状态点加 title tooltip（「运行中」「待重跑：上游参数已修改」等）。
- **为什么**：双通道编码（颜色+形状）是状态系统的底线。待重跑橙点尤其需要文字解释——「为什么它变黄了」是新用户必然的一问。

### P1-6 强调色使用点超编

- **现状**：首屏可见 accent 使用：logo 图标、选中卡描边、标签页 active、发送钮、「NEW」徽章、缩略图 hover 描边、连线流光——超过「每屏 ≤2 处」的克制标准。
- **改成什么**：收敛到 3 个固定席位：发送钮（主 CTA）、选中态（描边+操作条 active）、运行反馈（状态点+流光）。「NEW」徽章去掉或改中性灰底；logo 图标改 `--fg` 单色；标签页 active 保留 accent（它承担导航定位职能）。
- **为什么**：工具型产品的 accent 是稀缺资源，处处强调 = 处处不强调。发送钮必须是全屏最绿的那个点——它是用户每分钟的落点。

## 三、P2 精修项（交互完整性与工程严谨）

| # | 现状 | 改成什么 | 为什么 |
|---|---|---|---|
| P2-1 | 发送钮永远可点 | 输入为空且未选卡片/参考图时置 disabled（opacity .45 + cursor not-allowed） | 空提交是无效 API 调用，API 虽便宜也不该浪费；且空跑结果的反馈会污染状态语义 |
| P2-2 | 空画布、空图库无引导 | 空画布中央放一张虚线轮廓引导卡（「拖入或点击上传第一张产品图」+ 上传图标）；空图库显示一行 12px 灰字「生成的图会自动收进这里」 | 第一版就 2 步，空态是用户的第一屏，必须告诉他从哪开始 |
| P2-3 | 上下文悬浮条无边界钳制 | 操作条/指令面板定位加 clamp：水平限制在画布可视区内（左右各留 12px）；卡片贴近视口顶部时操作条翻转到卡片下方、指令面板翻转到上方 | 卡片拖到边缘面板飞出视口 = 选中即失控，画布工具的高频事故点 |
| P2-4 | 连线中点「+」常显 | 改为 hover 连线时才浮现（opacity 0→1，150ms）；第一版「插入步骤」本就是第二版功能，按钮点击仅 toast 演示 | 常显小圆点是持续视觉噪音；温馨画布要干净，节点间的留白让图呼吸 |
| P2-5 | 无键盘可达性 | 桌面工具最低集：Esc 取消选中并收起悬浮层、Delete 删卡（带确认）、Enter 聚焦指令输入框；所有按钮补 `:focus-visible` 焦点环（`--focus-ring`） | 键盘流是专业工具的效率命脉；焦点环是 a11y 底线 |
| P2-6 | 卡片高度固定 200px | 卡片容器 `aspect-ratio` 跟随节点参数（3:4 参数 → 280×373）；横向卡片（4:3）同样适配 | 参数 chip 写着 3:4，卡片却是横版图，图文不符会侵蚀参数系统的可信度 |
| P2-7 | 无 `prefers-reduced-motion` 支持 | 媒体查询下：脉冲、扫描光、流光全部退化为静态（运行中=实线亮绿+静态状态点） | 动效敏感用户的硬性无障碍要求 |
| P2-8 | 历史缩略图 84px 偏小、无元信息 | 图库列宽 200→216px，缩略图升至约 92px；hover 显示 title（时间 + 来源节点名） | 拖拽目标 ≥88px 才不容易误拖；找不到「上次那张」时元信息是唯一线索 |
| P2-9 | toast 定位 `bottom:190px` 魔数 | 改为相对指令面板的动态定位，或固定 `bottom: 24px` 贴视口底部 | 指令面板位置随选中卡片移动，魔数定位在面板收起时会悬在半空 |
| P2-10 | 滚轮缩放步进 0.92/1.08 无档位感 | 保持连续缩放，但加 25%/50%/100%/200% 快捷档位（Ctrl+0 复位 100% 并居中） | 连续缩放找不到「100% 看真实像素」的锚点，出图检查必须能回到 1:1 |

## 四、Advisory（建议项，不阻断）

1. **产品名与 logo 文案**：顶栏仍写「Infinite Canvas」，与 2.0 「园艺电商视觉流水线」的定位有距离。建议保留英文名作为产品名（品牌资产），但在 logo 旁或关于页确立中文定位语，如「园艺视觉工作台」。纯建议，等用户拍板。
2. **指令面板宽度 680px 偏重**：贴在 280px 卡片下方时横向大幅超出，视觉重心失衡。建议选中单卡时面板宽度向卡片靠拢（`min(520px, ...)`），多选/框选时才放宽到 680px。
3. **「标记」标签页的语义**：当前图标是靶心，建议「标记」页定位为「局部重绘的涂抹/框选入口」，与第二版对话 Agent 的「换成侘寂风」指令形成互补——这部分等 PM 的 PRD-v2 对齐后再定。
4. **深色主题默认时机**：园艺电商视觉工作多在白天采光环境，建议默认浅色、记忆用户选择，不做跟随系统自动切换（避免出图校色时主题突变）。

## 五、Token 基调用摘要（详见 design-tokens-draft）

- **色板**：暖米白 `#FAF6F0` / 鼠尾草绿 `#7C9A72` / 暖棕黑 `#211E1B`（深），全量 17 语义色 × 双主题
- **状态五态**：灰 `#C9C2B6` / 亮绿脉冲 `#7C9A72` / 深绿 `#4A7C59` / 琥珀 `#E0A458` / 陶土红 `#CE6A56`
- **圆角**：8 / 12 / 16 / 20 / full 五级
- **阴影**：`--shadow-rgb` 通道化，浅 `120,100,80` / 深 `0,0,0`，三级阶梯
- **字体**：display Nunito（本地打包）+ body 系统栈 + mono JetBrains Mono
- **动效**：fast 120ms / base 180ms / slow 300ms，脉冲 1.6s、扫描 1.6s、流光 0.6s，全量 reduced-motion 降级
