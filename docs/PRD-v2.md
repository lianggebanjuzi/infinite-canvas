## 一、产品定义

**一句话**：为园艺电商三维视觉设计师个人打造的垂直 AI 生图流水线画布——预设流水线、参数化联动、分段执行，把"改一个词重跑全流程"的手工劳动消灭掉。

**目标用户（唯一）**：作者本人，26 岁，园艺产品三维电商视觉设计师。工具做给他自己上班用，无第二用户假设，不对外发布。

**核心问题**：现用 Google AI Studio Flow，每周浪费 ≥3 小时在"改参数→手动重传→重跑全链→结果散落各处"的重复操作上，且频繁被"审核/额度/网络"三件套打断出图。1.0 版死于"通用画布撞车 + API 贵"的负反馈循环；2.0 的前提是 API 价格已崩、场景回归（新工作每天在园艺电商视觉链上）。

**不做什么（定位红线）**：不做通用无限画布，不拼便宜，不正面刚 ComfyUI/即梦/Liblib 的生图能力本身——我们吃的是"生图之后的工作流编排"这块结构盲区。

## 二、第一版范围（用户已锁定）

流水线完整骨架为 5 步，**第一版只做前 2 步闭环**：

```
① 输入产品图 → ② 换风格 →（③ 生成复现 JSON → ④ 3D 复现 → ⑤ 场景合成，后续版本）
```

第一版四块能力，缺一不可：

1. **2 步闭环**：输入产品图节点 + 换风格节点，模板预设、默认连好，拖图即用
2. **参数化联动**：改上游输入（换图/改关键词/改模型/改比例）→ 下游自动标"待重跑"（脏标记）
3. **分段执行**：跑一段看一段，满意再跑下一段
4. **选中运行**：框选节点 → 只运行选中的那一段

**失败处理（第一版边界，用户拍板）**：只做"节点红点 + 失败原因提示"，不做自动切供应商、不做一键换源。依据：用户真实失败主因是网络问题（超时/代理不稳），不是审核拦截；失败时人工看一眼原因、重试或换网络即可，自动容错的投入产出不成立。

**验收唯一标准**：上周出不了的那几张图，用它能不能出来；用户每周愿意主动打开几次。

## 三、用户故事（第一版完整使用流）

**US-1 导入产品图**：用户打开应用，画布上已按模板摆好"输入产品图"和"换风格"两个节点且默认连好线。用户从左侧历史图库拖入（或本地上传）一张园艺产品白底图到输入节点，节点卡片显示大图，状态点为灰色（未跑）。

**US-2 设参数**：用户选中换风格节点，指令面板从卡片下沿浮现，填入风格关键词（如"侘寂风庭院角落、晨光、陶土质感"），选择模型和出图比例/分辨率（模型参数以 chip 形式呈现），点圆形发送钮。

**US-3 跑换风格**：系统沿连线执行：换风格节点状态点变绿色脉冲、连线显示流光动画、卡片有扫描光效果。完成后状态点变深绿，结果图直接占满卡片。

**US-4 改关键词 → 下游标脏**：用户对结果不满意，把关键词中的"晨光"改为"阴天柔光"。系统立即将换风格节点状态点变橙（待重跑）。若未来链路加长，所有下游节点一并标橙。

**US-5 分段重跑 / 选中运行**：用户框选换风格节点（或加一个下游节点一起框选），点运行，系统只执行选中的节点及其必要的上游依赖，不动已完成且未标脏的部分。

**US-6 失败看红点**：执行中网络超时。换风格节点状态点变红，悬停（或点击）显示可读失败原因（如"供应商请求超时，请检查代理或稍后重试"）。已完成节点的结果不受影响，用户处理后选中该节点重跑。

**US-7 保存与复用**：用户保存项目为 .icproj，下次打开恢复画布、参数与结果引用；产出图自动进入左侧历史图库，可再拖入画布作输入。

| 功能 | 说明 |
|------|------|

| 砍掉项 | 原因 |

| 换技术栈（Electron/Tauri） | 已定：pywebview + TypeScript/Vite 不变 |

## 五、验收标准（EARS 格式）

**AC-0（产品级唯一验收标准）**：When 第一版交付后，用户用上周在现有工具（Google AI Studio Flow）中出不了图的同批产品图执行完整 2 步闭环，系统必须能产出可用的风格化结果图；且交付后四周内，用户每周主动打开本工具不少于 3 次（以本地使用日志为凭）。

**AC-1（模板即用）**：When 用户新建项目，系统必须在画布上自动生成"输入产品图"和"换风格"两个节点并完成默认连线，无需用户手动搭建。

**AC-2（参数化联动）**：When 用户修改任一上游节点的输入（替换图片、修改关键词、切换模型、修改比例或分辨率），系统必须立即将该节点的全部下游节点状态点置为橙色（待重跑），且不自动触发执行。

**AC-3（分段执行 / 选中运行）**：When 用户框选一个或多个节点并触发运行，系统必须只执行选中节点及其处于未完成或待重跑状态的上游依赖，已完成且未标脏的节点不得重复执行。

**AC-4（失败红点）**：If 节点执行失败（含网络超时、代理异常、供应商报错），系统必须将该节点状态点置红并展示可读的失败原因，已完成节点的结果必须保留不受影响，且用户可在处理后仅重跑失败节点。

**AC-5（运行中状态）**：While 任一节点正在执行，系统必须在其上游连线显示流光动画、节点状态点显示绿色脉冲，且不得使用文字日志作为主要运行反馈。

**AC-6（运行中改参保护）**：While 节点正在执行，If 用户尝试修改该节点参数，系统必须阻止修改并提示"运行中不可修改，请先停止或等待完成"。

**AC-7（持久化）**：When 用户保存项目，系统必须将节点、连线、全部参数、结果图引用写入 .icproj 文件；When 用户重新打开该文件，系统必须完整恢复画布状态。

**AC-8（供应商前置校验）**：If 运行所需供应商未配置有效 API Key 或代理未就绪，系统必须在执行前阻止运行并给出明确配置指引，不得静默失败。

## 六、轻量竞品验证（2026-08-11）

**结论：重启方案的差异化判断仍然成立，无需调整方向；两处竞品动态需留意。**

| 竞品 | 验证结果 | 对第一版的影响 |
|------|----------|----------------|
| 即梦（字节） | 2026 年初全量开放"无限画布"，集成 Agent 智能共创（自然语言指令驱动画布）、工单模式、图层级编辑、跨模态联动。**未见**"改上游参数自动标脏下游/分段重跑"的工作流编排能力，仍是"逐资产生成 + 编辑"模式 | 主结论不变：它不碰参数化流水线。但其 Agent 共创与我们 P1 预留的"对话 Agent"撞型，届时差异化必须落在垂直流水线语义上 |
| Liblib | LiblibAI 2.0 工作流编辑器基于 ComfyUI，ComfyUI 引擎天然有节点缓存（只重跑变更节点）；另推出 LibTV（2026 年 3 月），在**视频**领域做了"无限画布 + 节点工作流 + 上游输出即下游输入"，方向与我们一致但领域不同 | 间接验证了"节点联动画布"的市场方向；但 ComfyUI 系面向专业用户、需自建流程，无园艺电商垂直预设，不构成直接对位 |
| ComfyUI / Google AI Studio Flow | 无新增变化，引用方案原结论：前者是专家自建工具，后者是用户当前痛点来源（流程割裂、审核/额度/网络三件套） | 维持原判断 |

**证据可靠性说明**：竞品信息来自公开搜索结果，其中部分内容源为 SEO 聚合站，可靠性中等；关键结论（即梦无脏标记/分段重跑语义、Liblib 系为 ComfyUI 专家工具）与多源信息一致，采信。

## 七、非功能需求

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 应用冷启动 < 5s；画布操作（拖卡/缩放/框选）60fps 无卡顿；状态点/流光动画不阻塞主线程 | P0 |
| 可用性 | 单节点失败不崩溃、不丢已完成结果；执行中断后可从断点状态恢复 | P0 |
| 安全 | API Key 仅本地存储、不明文写入 .icproj、不上传任何第三方；所有供应商请求走可开关的代理通道 | P0 |
| 兼容性 | Windows 桌面（pywebview）；前端兼容其内嵌 Chromium 内核即可，不做多浏览器适配 | P0 |
| 可访问性 | 状态点五态同时以形状/文字辅助区分，不单纯依赖颜色（红/橙/绿色弱场景） | P2 |
| 图标与文案红线 | 全部图标使用统一 SVG 描边图标方案（具体图标库选型由架构师锁定）；禁止用 emoji 充当功能图标；禁止紫粉渐变；禁止空洞占位文案 | P0 |
| 测试底线 | 仅覆盖两处：项目序列化/反序列化、执行失败容错路径 | P0 |

## 八、数据埋点（单人工具精简版）

无后端、无分析平台，埋点落地为**本地使用日志**（usage.log，仅本地、不上传），服务唯一验收标准的度量：

| 事件 | 记录内容 | 用途 |
|------|----------|------|
| app_open | 时间戳 | 度量"每周主动打开几次"（AC-0 的直接证据） |
| pipeline_run | 节点数、耗时、成功/失败 | 出图成功率趋势 |
| node_failed | 失败原因分类（网络/代理/供应商/其他） | 验证"失败主因是网络"这一前提是否持续成立 |
| image_accepted | 结果图被导出/入图库 | 度量"出不了的图能出来了" |

## 九、边界条件

- **空状态**：新项目画布非空（模板节点即默认内容）；历史图库为空时显示引导文字"拖入第一张产品图开始"
- **错误状态**：见 AC-4 / AC-8；失败原因文案必须是人话（"供应商请求超时"），禁止直接展示原始报错堆栈
- **加载状态**：执行中见 AC-5；项目打开时大图走懒加载，先占位框后出图
- **边界值**：单项目节点数第一版按模板固定为 2，无需处理大规模节点性能；输入图限制为常见格式（jpg/png/webp）且单张 ≤ 20MB
- **并发**：同一时刻只允许一个执行任务；执行中再次触发运行须排队或拒绝并提示
- **离线**：除供应商调用外的全部功能（画布、编辑、保存、图库浏览）离线可用
- **权限拒绝**：本地文件读写失败（如磁盘满/只读目录）时明确提示并保留内存中项目不丢
