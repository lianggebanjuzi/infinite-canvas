## 3. 关键决策与实现

- **无迁移纪律**：persistence 删 migrateNode → `normalizeNodeV4` 严格归一；restore 非 v4.0 → toast「旧项目不兼容，将新建空白项目」return false（不清当前画布）；collect version '4.0'。
- **数据收集唯一权威**：`flowState.getUpstreamOutputs(id)` = 本节点 refImages ∪ 直接上游 image 图（一层不穿透）+ 按连线顺序/上游 id 序的 text 输出；`getReferenceImages` 收窄为显示别名。
- **文本走线（M1）**：text 运行 = 上游图（data:image 过滤）+ 上游文拼接 + 命令 → 结果写回自身 + 下游标 stale；**删除** applyTextToDownstream（旁路）/ runImageReverse（反推游离）/ 反推开关 UI。
- **图操分家（M2）**：gen 永不写回自身；`createResultImageNode` 永远建 image 产物（parentId + trace + edge + batchId 透传 + lastResultUrl 回写 gen）；重跑顶掉旧产物、锁定保留+标 stale；扩图 = image 右键建 gen(mode='outpaint') 预填 + 连上游图 + 参数持久化；多文本按连线顺序拼接、手动改写覆盖。
- **一键重跑（M3）**：`runAll` 增强为默认收集全部 stale 且可运行（text/gen，image 跳过）→ 拓扑序 → 失败停止；底栏新增「运行整条链」按钮。

## 4. 修复记录（Bug-1）

**outpaint 空 prompt 被 early check 拦截**（QA Round 1 发现）：`runGenBatch` 的 `!effectivePrompt` 提前返回拦截了 mode='outpaint' 空 prompt（永远到不了分支内 `OUTPAINT_PROMPT_PREFIX` 兜底），导致 image 右键「扩图」空描述直接发送必失败。修复：条件改为 `!effectivePrompt && params.mode !== 'outpaint'`（commit `3b8bf70`，1 处 2+/1-）。QA Round 2 验证：outpaint 空 prompt → done + 产物 trace outputType='outpaint' + batchId 透传；draw 行为不受影响。

## 5. 遗留问题（非阻断）

**需产品/架构裁决（多跳链边角）**：
- R1 `_topoSort` 依赖节点数组序：正常创建序下正确，restore 后节点序倒置（人工构造）会下游先跑；建议沿「经中间 image 产物」传递依赖。
- R2 中间产物不重指：gen1 重跑时中间 image1（有出边→gen2）被保留+标 stale，gen1 新建 image1' 但 gen2 连线仍指旧 image1；建议产物替换时重指下游手动边。

**需手动回归（DOM/pywebview 依赖）**：gen 空壳卡 CSS 视觉「一眼可分」；底栏按钮启停/计数；cmd-panel 无反推 chip；v4.0 保存/打开往返；批次卡/配方卡视觉；扩图交互面板；撤销/重做各手势实机。

**非缺陷（设计确认）**：text 无命令不自动重跑（canRun 拦截）；outpaint 重跑不顶掉（逐次累加）；旧 assets.json/history.jsonl 保留容错加载（不删全局资产）。
