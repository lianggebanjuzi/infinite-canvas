# Infinite Canvas 3.0：参考 Infinite Atelier 的工作流重构实施规范

> 文档用途：本文件是交给后续编码 Agent 的**实施规格**，不是灵感笔记。Agent 应按本文的阶段、边界、验收条件实施并逐阶段验证。
>
> 产品方向：借鉴 Infinite Atelier 的工作方式与完成度，使用 Infinite Canvas 自己的 TypeScript + PyWebView + Python 后端 + `.icproj` 数据体系实现。**不复制其源码、组件、视觉、文案、Logo、提示词封面或导演台内容。**
>
> 参考对象：<https://github.com/GuiYi-Xi/infinite-atelier>。该项目当前的关键工作方式是“直接上游节点提供生成上下文；点击当前节点才执行；操作在右侧产生结果节点”，而不是自动执行整张 DAG。

## 0. 给 Agent 的第一条指令

本次不是重写 Infinite Canvas，也不是构建 ComfyUI，也不是把现有项目改成 React。

目标是把现在已经存在的生成、连线、批次、历史、资产、项目保存能力，重新组织成一个用户一眼能看懂的 AI 视觉创作工作台。

用户应该感受到的是：

```text
导入一张参考图
  → 在图上直接说想怎么改
  → 得到紧贴源图的新结果
  → 从任意结果继续尝试另一个方向
  → 随时从资产、历史、提示词中取回内容
  → 保存为本地项目，之后仍能打开和继续。
```

不要把工作重心放在设计一套新的“作品实体 / 创作记录实体 / 时间线实体”三层数据库。现阶段不需要它。现有 `FlowNode`、`FlowEdge`、`GenerationTrace`、历史和资产库已经足以承载目标体验；只有在交互确实被现有数据模型阻碍时，才做**向后兼容的小字段扩展**。

### 0.1 必须遵守的范围

- 保持本项目自己的暖白画布、浅色卡片、柔和绿色强调色和中文创作语境；不要模仿参考项目的深色工业感、排版、图标、尺寸、动画与文案。
- 保持 PyWebView 桌面应用、Python 后端、供应商配置、`.icproj`、本地图片原图保存与现有 API 边界；不要迁移为浏览器 LocalForage、React、Zustand 或参考项目的存储方式。
- 不删除现有扩图、图片生成、文本反推、批次队列、历史图库、资产库、对比面板、项目读写能力。
- 不引入音频、视频、导演台、多媒体节点作为本轮前置条件。参考项目的多媒体广度可以以后再评估；3.0 第一目标仍然是图片创作。
- 不复制参考项目的代码。可以基于本文件描述的**抽象行为**独立实现。
- 不修改用户已有的无关工作区改动；开始前先运行 `git status --short`。当前工作区可能是脏的，尤其有历史文档删除记录，不能顺手恢复、删除或提交它们。

### 0.2 每个 Agent 回合的工作纪律

1. 只推进一个小阶段或一个可验收切片，不要大爆炸式改造。
2. 改动前列出会碰到的文件和用户可见行为。
3. 任何 `.icproj` 格式、`FlowNode` 或 `FlowEdge` 的新增持久化字段，都必须：
   - 是可选字段；
   - 旧项目加载时给出确定的默认值；
   - 在 `persistence.ts` 的归一/迁移路径中处理；
   - 有最小验证用例。
4. 每个切片至少执行 `npm run typecheck`；改动构建入口、HTML、样式、模块引用或打包配置时执行 `npm run build`。
5. 改动扩图路径时，额外执行交接说明中规定的扩图 smoke 回归。
6. 不因“看起来简洁”而删除尚未替代的旧入口；先隐藏、迁移、验证，再决定是否移除。

## 1. 当前项目真实基线

### 1.1 技术与持久化边界

| 层 | 当前实现 | 本轮处理原则 |
|---|---|---|
| 桌面壳 | Python `main.py` + PyWebView | 保持不动 |
| 前端 | 原生 TypeScript + Vite + DOM 模块 | 保持，不迁 React |
| 画布状态 | `src/v1/state/flow-state.ts` 的单例 `flowState` | 继续作为节点与边的事实源 |
| 项目文件 | `.icproj`，由 `src/v1/persistence.ts` 读写 | 保持版本兼容 |
| 后端 API | `backend/api/unified_api.py`、`provider_api.py` 等 | 不重做后端协议 |
| 图片原图 | 后端本地保存；前端通常留缩略图 + `imageOrigin.path` | 必须保留，图生图优先取原图 |
| 资产库 | `src/v1/asset-store.ts` + 后端资产索引 | 扩展体验，不另起存储 |
| 生成历史 | `src/v1/history-persist.ts`、`ui/history-drawer.ts` | 保留为可回看的全局/项目辅助视图 |
| 批次任务 | `state/batch-store.ts`、`engine/batch-queue.ts`、`run-engine.ts` | 保持原有重试、失败、进度语义 |

### 1.2 当前节点、连线与生成事实

当前不是没有信息流，而是信息流没有被翻译为清楚的用户体验。

```text
素材/图片节点 ─┐
文字节点 ──────┼──→ 图片生成节点 ──→ 图片结果
手动参考图 ─────┘
```

当前关键规则：

- `FlowNode` 存坐标、类型、参数、展示图 `imageUrl`、原图引用 `imageOrigin`、主动挂载的 `refImages`、状态、批次结果、`parentId` 与 `trace`。
- `FlowEdge` 只存 `from → to`；运行时由目标节点读取直接上游，不自动执行整张画布。
- `flowState.getReferenceImages(nodeId)` 合并：当前节点手动参考图在前 + 直接上游图片输出在后；只读一层，不 BFS 递归。
- `flowState.getUpstreamTextPrompts(nodeId)` 读取直接上游 `text-gen` 的实际输出，按连线创建顺序拼入最终提示词。
- `runEngine.composeImagePrompt` 把上游文本与当前节点的 prompt 合成。
- `runEngine._resolveGenerationReferenceImages` 会在发起请求时优先用上游图片的原图文件，拿不到才降级缩略图。
- 单张生成通常写回当前生成节点；批量生成把候选收在同一张卡的 `generatedImages`；扩图及部分结果路径会自动建立右侧结果卡。
- 当前未提交的 3.0 小改动已经添加“继续创作”：从任意已有图片创建一个右侧下游 `image-gen` 节点，自动连线并聚焦输入框。

### 1.3 当前优势与当前短板

**应该保留的优势**

- 比参考项目更完整的本地项目文件和原图读回路径。
- `GenerationTrace` 已保存 prompt、模型、比例、分辨率、参考图、创建时间、输出类型、批次/任务编号。
- 批次状态、失败重试、取消、历史和扩图的工程化能力已经存在。
- 连线有类型契约、防环、修改上游后标记下游 `stale` 的机制。

**必须修正的体验短板**

- 用户看到的是“节点卡 + 操作条 + 参数芯片”，不容易先理解“我从这张图可以继续做什么”。
- 同一条线既可能代表参考输入、提示词输入、操作来源、结果版本，视觉上没有明确区分。
- 资产库和历史图库是两个独立抽屉，入口与用途不够像一个整体工作台。
- 项目入口弱；用户一打开就是画布，缺少“项目 / 最近工作 / 从素材开始”的清晰起点。
- 提示词库已有，但它是命令面板的一个功能，尚未成为工作台内易发现、易插入的资源。
- 已有的技术追溯信息多藏在数据里，没有转成用户可见的“来源”和“本次使用了什么”。

## 2. 参考项目真正值得借鉴的东西

不要把参考项目误解为复杂的节点工作流引擎。它的本质很简单：

```text
一个节点的直接输入 = 本次操作的上下文
点击该节点 = 只执行这一次
一次操作的结果 = 在右侧自动生成可继续使用的新内容
```

本项目应借鉴以下五条行为原则：

1. **画布是创作桌面，不是工程流程图。** 连线让用户知道“这张图/这段文字参与了哪里”，但用户不需要理解执行图。
2. **图片是最自然的发起点。** 选中图片后，优先显示继续创作、扩图、局部修改、变换等语义动作，而不是一排模型参数。
3. **上下文是局部、显式、可见的。** 当前节点只消费直接连接的图片/文字/参考，不神秘地读取整张画布。
4. **结果靠近来源。** 操作结果自动放在来源右侧；用户可直接从结果继续，不需要重新手工接线。
5. **资源在侧栏可取回。** 资产、历史、提示词不是另一个产品，而是当前画布随时可以拿来用的内容来源。

本项目不应照抄以下部分：

- 任何 React 组件、状态管理、浏览器存储方案；
- 它的多媒体/导演台功能规模；
- 它的界面层级、图标、颜色、圆角、字号、英文文案或品牌素材；
- “所有内容都放在浏览器同一 origin 存储”的项目模型。

## 3. 3.0 的产品定义（本轮最终口径）

### 3.1 一句话定义

**Infinite Canvas 3.0 是以图片为中心、用本地项目保存的 AI 视觉创作工作台。**

它不承诺做影视分镜工具，也不承诺做通用 DAG 引擎。它的价值是：用户能在一张画布上导入灵感、组织提示词、生成/编辑图片、比较结果并持续往下做，而不丢失当前上下文。

### 3.2 首期成功标准

一个首次使用者在不阅读说明的前提下，应能完成：

```text
新建项目
  → 从资产库导入或拖入一张图
  → 选图，看到“继续创作”
  → 输入一句想法并生成 2 张候选
  → 在候选中选一张，继续创作或扩图
  → 在左侧找到此前导入的图和本次生成历史
  → 保存、关闭、重新打开项目，图、位置、连线、参数均仍在。
```

以下事实应对用户可见：

- 我当前选中的是什么：素材、待生成步骤、已生成结果、失败步骤。
- 当前生成会用到什么：哪些参考图、哪些上游文字、什么模型与主要任务设置。
- 这张结果来自哪里：至少能看出源图片/上一步与动作类型。
- 继续做不会覆盖旧图：会创建新结果或保留历史候选。

### 3.3 非目标

- 不要求首期支持音频、视频、群组、复杂配置节点。
- 不要求首期增加线性时间线。
- 不要求首期让每个生成结果自动同步到“永久资产库”；先把“保存到资产库”和“插入画布”做得自然可靠即可。
- 不把模型、分辨率、张数完全藏掉；它们应进入“更多设置”或任务摘要，不抢占创作主线。

## 4. 目标信息流与语义规则

### 4.1 三种用户看得懂的连线语义

底层仍可继续是 `FlowEdge { id, from, to }`，但 UI 与交互必须区分下面语义。第一阶段允许通过“节点类型 + 操作来源”推断；若推断不稳定，再引入可选 `relation` 字段。

| 语义 | 例子 | 当前运行时含义 | 目标视觉 |
|---|---|---|---|
| 参考输入 | 图片 A → 继续创作 B | A 的原图加入 B 的参考图 | 细实线，靠近 B 显示小缩略图/“参考”提示 |
| 文字输入 | 文本 A → 图片 B | A 的输出拼进 B 的 prompt | 细虚线或文字图标线，B 面板显示文字摘要 |
| 结果来源 | 操作步骤 A → 结果 B；扩图 A → 结果 B | B 是 A 的输出/派生结果 | 更明显的方向线/箭头；B 卡显示“基于 A” |

不要要求用户手工选择“线类型”。自动操作创建的线必须带确定语义；手动连线按来源/目标类型推断。

### 4.2 兼容性优先的数据扩展建议

除非当前阶段确实需要，不要一次性修改所有旧 `.icproj`。如需增强连线语义，采用下面的兼容策略：

```ts
// 在 src/v1/types/flow.d.ts 中：新增为可选字段，旧文件无字段照常加载。
type FlowEdgeRelation = 'reference' | 'text-input' | 'result' | 'generic';

interface FlowEdge {
  id: string;
  from: string;
  to: string;
  relation?: FlowEdgeRelation;
}
```

归一默认值规则：

1. `from` 是 `text-gen`、`to` 是 `image-gen`：`text-input`。
2. `to.parentId === from.id`：`result`。
3. `from` 是图片/素材、`to` 是图片生成：`reference`。
4. 其余：`generic`。

注意：这是**展示与交互语义**，不是新 DAG 引擎。`runEngine` 仍然只按现有规则消费直接上游资源。

### 4.3 生成上下文的固定口径

任何新 UI 或快捷动作不得私自拼装 API 请求。生成上下文唯一来源仍是现有状态/引擎方法。

```text
最终提示词 = 直接上游文本输出（按连线顺序） + 当前图片节点自己的 prompt
最终参考图 = 当前节点主动挂载 refImages + 直接上游图片输出（去重保序）
实际提交图 = 如有 imageOrigin.path 优先读取原图，否则退回展示图
```

明确不做：

- 不递归合并祖先节点的所有图片和文本；那会让用户无法预测本次到底传了什么。
- 不让连线改变当前节点的模型、比例、张数，除非未来单独设计“配方节点”并明确其优先级。
- 不自动运行所有下游节点。

### 4.4 结果与重跑规则

| 场景 | 必须行为 |
|---|---|
| 从素材点“继续创作” | 新建右侧 `image-gen`，保留素材，自动建立参考关系，聚焦 prompt |
| 从结果点“继续创作” | 与素材相同；支持多个下游分支 |
| 单张生成 | 可以写回当前空步骤节点；绝不能覆盖上游源图 |
| 多张生成 | 保留同批候选，并能选择其中一张继续创作；不要无声丢弃未选候选 |
| 扩图/局部修改/放大等派生操作 | 结果紧贴源图右侧/右下，建立来源关系；失败节点保留供修改后重跑 |
| 用户修改了参考线/文本输入 | 当前节点及所有下游标 `stale`，但不删除已有图；用户决定是否重跑 |
| 从画布删除节点 | 只删除节点及连接；不自动删除历史条目、资产库原图或本地生成文件 |

## 5. 页面与布局目标

### 5.1 目标不是重做成多页 Web 应用

本项目是桌面工具。可以在一个 PyWebView 窗口内引入“项目主页 / 工作台”两种显著状态，但不要为模仿参考项目而强行加浏览器式路由。

建议的界面层级：

```text
应用启动
├─ 项目主页（最近项目 + 新建 + 打开 + 可选模板）
└─ 创作工作台
   ├─ 顶栏：返回项目、项目名、保存状态、撤销/重做、设置、窗口控制
   ├─ 左侧资源抽屉：资源 / 历史 / 提示词 三个页签
   ├─ 中央：无限画布
   ├─ 选中图片：图片动作条 + 就近任务面板
   └─ 底部：缩放/适配、任务状态、保存与次要工具
```

### 5.2 项目主页（P1）

项目主页是“完成度”最明显、但不该碰生成底层的第一块。

**最小功能**

- 显示产品名和一句自己的中文定位；不复制参考项目品牌文案。
- 主按钮：`新建创作项目`。
- 次按钮：`打开本地项目`。
- 显示当前会话能识别的最近项目。若现有后端没有最近项目索引：
  - 第一版允许只显示当前项目或暂不持久化最近列表；
  - 不要为了做主页重做项目文件格式；
  - 可在 `settings.json` 增加兼容的 `recent_projects` 列表，但要由后端 API 单独读写并过滤不存在的路径。
- 新建后直接进入空画布，显示低干扰的“导入图片 / 新建图片创作 / 从提示词开始”引导。

**不要做**

- 不在主页嵌入巨大营销视觉、在线视频、参考项目风格海报。
- 不把首页当作必须联网的账户中心。

### 5.3 工作台：左侧统一资源抽屉（P2）

现有“历史图库”和“资产库”是两个互斥滑出抽屉。目标是把它们统一为一个可理解的资源入口，而不是强制重写 store。

建议命名与页签：

| 页签 | 数据源 | 首期行为 |
|---|---|---|
| 资源 | `assetStore` | 搜索、标签、预览、拖入画布、从画布移除不影响资源 |
| 历史 | `historyDrawer`/`historyPersist` | 查看最近生成、按 prompt/模型检索、拖入画布、保存到资源 |
| 提示词 | 现有 `workflow-library` 或提示词库数据 | 搜索、预览、点击插入当前 prompt、可收藏当前 prompt |

实现可以先保留三个现有模块和数据源，只在 `left-capsule.ts`、`asset-drawer.ts`、`history-drawer.ts` 与 `index.html` 层合并外壳。不要在 P2 同时重写资产持久化、历史格式和提示词库格式。

**资源插入语义**

- 从资源/历史拖到画布空白：创建 `isAsset: true` 的图片节点。
- 拖到一个图片生成节点：作为该节点主动 `refImages` 加入，不自动生成。
- 点击资源卡的“放到画布”：以当前视口中心或可见空位创建素材节点。
- 点击历史卡的“继续创作”：先在画布放置素材/结果节点，再调用统一的 `createContinueStep`。

### 5.4 画布与选中态（P3）

画布应服务于“看图、比图、做下一步”。

**图片卡最低可见层级**

1. 图像本身；
2. 轻量状态：素材、生成中、失败、待重跑；
3. 来源摘要：`导入素材`、`基于「xx」`、`扩图结果` 等；
4. 批次候选入口（仅有多个候选时）；
5. 鼠标悬停时的次要动作：预览、加入资源、下载。

选中图片时，操作条按优先级显示：

```text
继续创作（主） | 扩图 | 更多：局部修改 / 多角度 / 放大 / 下载 / 加入资源
```

- “继续创作”必须是最左、最显眼但不过度夸张的主操作。
- 对素材节点，只显示确实可用的操作：继续创作、下载、加入/移出资源；不要展示未实现的多角度/打光/高清放大按钮。
- 对失败节点，首操作是“修改并重跑”，并显示失败原因；不要把失败节点伪装成普通素材。
- 对 `stale` 节点，显示“输入已变化，需重新生成”的明确状态，但不强制重跑。

### 5.5 就近任务面板（P4）

保留当前 `cmd-panel.ts` 的好处：操作发生在节点附近，不把用户赶到全局右侧栏。

任务面板应分两层：

**首屏只显示**

- 当前要做什么：`创作图片` / `扩图` / `基于图片修改`；
- 输入框；
- 参考图条（可见来源、可移除、可新增）；
- 对应任务的关键参数；
- 生成按钮与任务状态。

**更多设置折叠显示**

- 模型；
- 比例；
- 分辨率；
- 张数；
- 其他供应商特有参数。

扩图例外：比例、原图位置、缩放是首屏任务参数，必须继续显示实际摘要，例如：`扩图画布：16:9 · 原图居中 · 缩放 84%`。

**目标**：确保后续改造不会损坏当前 2.1 能力。

**操作清单**

1. 运行 `git status --short`，在交付说明中原样记录已有改动，不触碰无关文件。
2. 运行 `npm run typecheck`。
3. 运行 `npm run build`。
4. 运行现有扩图 smoke 回归：

### Phase 1：稳定“从图片继续创作”的主路径

**目标**：让用户不必理解节点创建，就能从素材或结果开始下一步。

**优先文件**

- `src/v1/ui/action-bar.ts`
- `src/v1/canvas/interactions.ts`
- `src/v1/ui/cmd-panel.ts`
- `src/v1/canvas/card-view.ts`
- `src/v1/styles/app.css`
- `src/index.html`

**实现要求**

1. 保留并完善当前 `createContinueStep(source)`：
   - 仅允许有实际图片或可用参考图的 `image-gen` 节点；
   - 创建 `source` 右侧的新 `image-gen`；多个下游时纵向错开，避免完全重叠；
   - 自动 `addEdge(source.id, node.id, { suppressStale: true })`；
   - 新步骤的 prompt 必须为空；模型、比例、分辨率可继承；张数默认 `1`；
   - 自动选择新节点并聚焦输入框；
   - 不复制图片文件、不覆盖源节点、不把源图写进新节点的 `refImages`（来源由边派生）。
2. 操作条与右键菜单都提供“继续创作”。两个入口必须调用同一个函数。
3. 图片卡显示来源摘要：素材为“导入素材”；派生节点为“基于 xxx”；不要为了摘要做递归大查询，最多四层并必须防环。
4. 创建后任务面板的参考图区能清楚显示源图已经加入本次上下文。
5. 补一条用户可见 Toast：`已以当前图片创建下一步，输入想法即可生成`。

**验收用例**

- 导入素材 → 继续创作 → 新节点出现且参考图可见 → 输入 prompt → 生成。
- 结果图 B → 连续两次继续创作 → B 有两个下游，互不覆盖。
- 删除下游步骤不删除 B、历史或已加入的资产。
- 从右键和操作条发起，状态一致。

### Phase 2：统一资源侧栏，不动底层数据

**目标**：用户能把“资源、历史、提示词”理解为当前画布的内容来源。

**优先文件**

- `src/index.html`
- `src/v1/ui/left-capsule.ts`
- `src/v1/ui/asset-drawer.ts`
- `src/v1/ui/history-drawer.ts`
- `src/v1/ui/workflow-library.ts`
- `src/v1/main.ts`
- `src/v1/styles/app.css`

**实现切片 A：统一入口，不重写内容**

1. 左侧只保留一个资源入口/一个抽屉外壳；内部显示 `资源 / 历史 / 提示词` 页签。
2. 第一版允许每个页签仍委托原组件渲染；禁止复制三份搜索、预览、拖拽逻辑。
3. 页签切换不应丢掉各自查询关键字；关闭抽屉时保留页签状态即可。
4. 资源卡必须有：预览、放到画布、移出资源；有配方时可复制 prompt。
5. 历史卡必须有：预览、放到画布、保存到资源、用作下一步；先复用已有动作，缺动作再新增。
6. 提示词卡至少有：搜索、插入当前节点 prompt、复制、收藏当前输入。不要在本阶段制作参考项目那样的封面体系。

**实现切片 B：插入规则统一**

新增一个小型协调函数/模块（名称示例 `src/v1/ui/resource-insert.ts`），集中处理：

```ts
insertImageAsAsset(url, origin?, position?): FlowNode
insertHistoryImageToCanvas(historyItem, position?): FlowNode
attachImageToSelectedGeneration(url): boolean
startCreateFromResource(url, metadata?): Promise<void>
```

禁止在 `asset-drawer.ts`、`history-drawer.ts`、`interactions.ts` 三处各自创建不同格式的素材节点。

**验收用例**

- 从资源拖入空白画布 → 出现素材节点，未触发生成。
- 从历史放到画布 → 可预览、可继续创作。
- 从资源拖到当前图片生成节点 → 只增加一个参考图，不创建意外节点。
- 历史图片“保存到资源”后，资源页即时出现；移出资源不删历史。

### Phase 3：让连线可读，而不是改变执行模型

**目标**：用户能区分“这是参考输入”与“这是结果来源”。

**优先文件**

- `src/v1/types/flow.d.ts`
- `src/v1/state/flow-state.ts`
- `src/v1/persistence.ts`
- `src/v1/canvas/link-view.ts`
- `src/v1/canvas/card-view.ts`
- `src/v1/canvas/interactions.ts`
- 相关 smoke 测试

**步骤**

1. 先检查仅凭 `parentId`、节点类型和参数能否稳定推断语义。
2. 若可稳定推断，先只做 `link-view.ts` 视觉表达，不修改 `FlowEdge` 格式。
3. 若不能稳定推断，再为 `FlowEdge` 加可选 `relation` 字段，严格按第 4.2 节兼容规则迁移。
4. 在边旁提供低噪音标签或 icon：`参考`、`文字`、`结果`。缩放很小时隐藏标签，仅保留线条区别。
5. 手动建立连接时保持现有 `canConnect`、防环、`stale` 语义。不要为了“自由”放松素材节点不能接收上游、文本拆分的特殊契约。
6. 自动创建结果卡、继续创作、扩图时应明确写入/推断正确关系。

**不得改变**

- 生成只读取直接上游一层的规则；
- `getReferenceImages` 的去重与顺序；
- 上游文本按连线建立顺序拼接的规则；
- 修改连接后下游标记 stale 的规则。

**验收用例**

- 素材图 → 创建步骤：显示“参考”，运行时仍按原图提交。
- 文本 → 图片生成：显示“文字”，最终 prompt 包含文本输出。
- 扩图/结果卡：显示“结果”，来源卡与结果卡可被识别。
- 删除/新增任一输入边：目标与子孙变 stale，但历史图片没有消失。
- 旧 `.icproj` 打开后无异常、无连线丢失。

### Phase 4：任务化图片操作与结果链

**目标**：把“卡片上的一堆能力”改成“我想对这张图做什么”。

**优先文件**

- `src/v1/ui/action-bar.ts`
- `src/v1/ui/cmd-panel.ts`
- `src/v1/ui/outpaint-panel.ts`
- `src/v1/engine/run-engine.ts`
- `src/v1/canvas/card-view.ts`
- `src/v1/canvas/interactions.ts`
- `src/v1/nodes/image-gen.ts`

**任务优先级**

| 任务 | 当前状态 | 本阶段要求 |
|---|---|---|
| 继续创作 | 已有雏形 | 完成 Phase 1 验收 |
| 扩图 | 已有稳定能力 | 保留为第一个完整任务范例 |
| 局部修改 | 尚未完整 | 先设计入口和任务面板，不要假装能用；功能实现另立切片 |
| 多角度 | 入口存在/能力待确认 | 未实现前放入“更多”并禁用或不显示，不能只 Toast 占主操作位 |
| 高清放大 | 同上 | 同上 |
| 下载 / 加入资源 | 已有基础 | 降为次要操作 |

**扩图不得回退**

- 从操作条和右键菜单均能创建扩图步骤；
- 有独立比例、原图位置、缩放设置；
- 能运行、失败后修改再运行；
- 结果可进入历史、批次追溯；
- 任务面板显示实际生效参数摘要；
- 相关 smoke 维持通过。

**结果布局约定**

- 自动结果默认在来源右侧；同一来源的并列候选纵向或扇形展开，不能盖住来源卡。
- 新结果出现后自动选择结果或保留来源选择应由任务决定：
  - “继续创作”创建的是下一步空步骤，选中它；
  - 生成结束后默认保留用户正在操作的节点，但让结果显著可见；
  - 用户点击某个候选后，把该候选设为卡内主视觉，并提供“以此继续创作”。
- 不要为了每一张批量图片都创建一个无限增长的结果卡；先保留现有卡内候选组，只有用户明确“放到画布/继续创作”时才实体化为独立节点（若当前数据结构需要）。

### Phase 5：项目入口与保存体验

**目标**：从“单画布工具”升级为“有项目感的桌面工作台”，但不破坏 `.icproj`。

**优先文件**

- `src/index.html`
- `src/v1/main.ts`
- `src/v1/persistence.ts`
- `src/v1/ui/bottom-bar.ts`
- `backend/api/project_api.py`
- 如确有必要，`backend/api/settings_api.py`

**第一版要求**

1. 应用启动后的默认状态明确：新建项目、打开项目，或进入轻量项目主页。
2. 工作台顶部显示项目名称、保存状态与“返回项目”的明确入口。
3. 使用现有保存/打开 API；不能改成自动将所有项目写到不透明浏览器存储。
4. 如果实现最近项目：
   - 只存本地路径、显示名、最近打开时间；
   - 打开前检查文件存在；
   - 移除记录不删除文件；
   - 后端失败时主页仍可新建/打开。
5. 新建项目不自动加载旧模板、不悄悄带入前一个项目的节点或资源。

**验收用例**

- 新建 → 导图 → 生成 → 保存为 `.icproj` → 关闭 → 打开，全部节点、连接、来源、批次候选与提示词状态恢复。
- 项目路径无效时显示可理解的错误，最近项目列表不会阻止正常打开。
- 保存失败不把 UI 伪装成“已保存”。

### Phase 6：可追溯信息的用户化展示

**目标**：把已经存在的 `trace` 数据变成有用的界面，而不是新增另一套数据库。

**优先文件**

- `src/v1/types/flow.d.ts`
- `src/v1/engine/run-engine.ts`
- `src/v1/canvas/card-view.ts`
- `src/v1/ui/result-viewer.ts`
- `src/v1/ui/history-drawer.ts`
- `src/v1/ui/asset-drawer.ts`

**功能定义**

在结果卡的“查看详情”或大图查看器中，显示：

```text
来源：导入素材 / 上一步图片 / 扩图结果
操作：文生图 / 图生图 / 扩图
提示词：实际提交的完整 prompt
参考：实际提交的参考图缩略图
设置：模型、比例、分辨率、张数
时间：创建时间
批次：第几批、第几项（存在时）
```

并提供：

- `以此继续创作`：调用统一继续创作逻辑；
- `复制提示词`：只复制实际 prompt；
- `放到画布`：对历史/资源图可用；
- `保存到资源`：对历史生成图可用。

**边界**

- `trace` 缺失的旧节点显示“历史配方不可用”，不能编造参数。
- `imageOrigin.path` 失效时预览退回缩略图，不能使整个详情面板崩溃。
- 不在本阶段实现“完全相同设置一键复现”，除非先核实供应商参数、原图、密钥与模型仍可用；复制 prompt 是安全的首期替代。

## 8. 详细行为验收矩阵

### 8.1 从图片开始

| 编号 | 操作 | 预期 |
|---|---|---|
| I-01 | 资源图拖到画布空白 | 新建素材节点，显示“导入素材”，不自动生成 |
| I-02 | 选中素材 | 首操作是“继续创作”，次操作是下载/加入资源 |
| I-03 | 点击继续创作 | 右侧新建空步骤，源图作为参考，输入框聚焦 |
| I-04 | 输入“雨夜霓虹”并生成 | 只使用该图片 + 当前 prompt；源图不变化 |
| I-05 | 从结果再点继续创作两次 | 形成两个可并存分支；不要求用户选覆盖/替换 |

### 8.2 文本、参考与连线

| 编号 | 操作 | 预期 |
|---|---|---|
| C-01 | 文本输出连到图片生成 | 文本进入最终 prompt；面板可见文本来源摘要 |
| C-02 | 两个素材图连到同一图片生成 | 两图均作为参考，顺序可预测 |
| C-03 | 给节点手动添加参考图 | 主动参考优先于连线图；重复图只提交一次 |
| C-04 | 修改/删除输入边 | 目标与下游标 stale；旧图仍可查看、下载、继续创作 |
| C-05 | 尝试造成环的连接 | 被拒绝，画布数据不变化 |

### 8.3 生成、候选、失败

| 编号 | 操作 | 预期 |
|---|---|---|
| G-01 | 张数设为 2 | 两个候选都可浏览，成功/失败状态准确 |
| G-02 | 一张成功一张失败 | 显示部分失败；可重试失败项；成功图不丢失 |
| G-03 | 生成中取消 | 不留下假成功；已完成的结果按既有规则保留 |
| G-04 | 上游原图有本地路径 | 图生图请求优先提交原图，而不是缩略图 |
| G-05 | 原图路径失效 | 回退缩略图或显示明确错误，不挂死 |

### 8.4 扩图

| 编号 | 操作 | 预期 |
|---|---|---|
| O-01 | 图片操作条创建扩图 | 建立可编辑扩图步骤，比例/摆放/缩放首屏可见 |
| O-02 | 调整比例、位置、缩放 | 摘要和实际请求参数一致 |
| O-03 | 扩图失败后改参数重跑 | 可恢复，不需要重建所有连线 |
| O-04 | 扩图成功 | 结果与源图有清楚来源关系，历史和批次可追溯 |

### 8.5 资源、历史、项目

| 编号 | 操作 | 预期 |
|---|---|---|
| R-01 | 历史图保存到资源 | 资源页立即出现；配方尽量带入 |
| R-02 | 从资源移除 | 只从资源索引移除，画布与历史不受影响 |
| R-03 | 历史图放到画布 | 建素材节点，可继续创作 |
| R-04 | 保存并重开项目 | 节点、边、位置、参数、来源、候选结果恢复 |

## 10. 推荐执行顺序与停止点

不要把本文当作必须一次做完的巨大 PR。推荐按下面顺序交付，并在每个停止点等用户试用确认。

| 交付批次 | 内容 | 停止点 / 用户能验证什么 |
|---|---|---|
| A | Phase 0 + Phase 1 | 从任意图继续创作是否顺手，结果/来源是否看懂 |
| B | Phase 2 | 资源、历史、提示词是否像同一个工作台入口 |
| C | Phase 3 | 连线是否更易读，同时没有破坏现有生成逻辑 |
| D | Phase 4 | 图片任务是否比“通用节点参数”更清楚；扩图是否仍完整 |
| E | Phase 5 | 项目入口、保存、打开是否给人完整产品感 |
| F | Phase 6 | 历史与来源详情是否真的帮助继续创作 |

若用户在 A 或 B 阶段认为方向不对，停止后续 UI 扩张，保留已验证的底层安全改动。不要因为本文存在而强行完成所有 Phase。

## 12. 最终决策记录

本轮 3.0 的方向已经从“先重构为独立作品/创作记录/画布摆放三层架构”，调整为：

> **先用现有节点、连线、trace、历史、资产和本地项目能力，做出图片优先、上下文明确、结果可持续分支的完整创作工作台。**

只有当后续真实使用证明下面的问题无法靠现有模型解决时，才重新评估独立作品实体或时间线：

- 同一张图必须同时摆放在多个画布且不能复制节点；
- 用户需要跨多个项目统一管理并追溯同一媒体对象；
- 大量分支与长期创作使历史/资源/节点无法满足回看需求；
- 需要独立于画布的严格版本树或时间线。

在此之前，产品完成度、清晰的信息流和稳定的创作体验优先。
