## 二、产品定义

### Product Goals（3 个正交目标）

1. **可复现（配方闭环）**：每张带 trace 的生成结果都能一键复现——参数级回填（prompt/模型/比例/分辨率/参考图）、一键重跑，且复现不破坏原结果。对应功能 A。
2. **可积累（成图库资产化）**：历史图库升级为成图库入口——成图/文本分区、可搜索、可采纳/锁定、状态跨会话持久化，好结果固定下来不被重跑顶掉。对应功能 B。
3. **可比较（评估入口）**：多张成图可并排对比、面板内直接采纳，淘汰的留在图库不污染画布主链。对应功能 C。

### User Stories

**功能 A · 复现**
- **A-US1**：As 设计师，I want 对一张生成结果点「复现」就能把原配方（prompt/模型/比例/分辨率/参考图）一键回填并重跑，so that 我不需要手工重新填写参数就能再次尝试同一配方。
- **A-US2**：As 设计师，I want 复现不破坏我原来的结果图，so that 我可以放心把复现结果与原图对比，而不是担心旧图被顶掉。
- **A-US3**：As 设计师，I want 从历史图库里的成图也能复现，so that 跨会话找回的图也能再跑一遍。

**功能 B · 成图库收口**
- **B-US1**：As 设计师，I want 历史图库里成图和文本记录分开展示，so that 我不会在图片网格里翻文字记录。
- **B-US2**：As 设计师，I want 对满意的成图标记「采纳」（自动锁定），so that 它不会被后续重跑顶掉，且成为我可复用的候选结果。
- **B-US3**：As 设计师，I want 按 prompt/模型关键词搜索成图，so that 生成几百张后也能快速找到目标图。
- **B-US4**：As 设计师，I want 锁定保护真正生效（重跑不删、不覆盖锁定图），so that 我放心重跑其它节点而不怕好结果被冲掉。

**功能 C · 对比面板**
- **C-US1**：As 设计师，I want 多选几张生成图后点底部「对比(n)」并排查看，so that 我能一眼比较差异。
- **C-US2**：As 设计师，I want 在对比面板内直接采纳最好的一张，so that 不用回到画布逐张操作。
- **C-US3**：As 设计师，I want 淘汰的图只留在图库里、不污染画布主链，so that 对比是一个纯评估动作。

## 三、需求池

> 优先级判定依据：P0 保证「复现闭环 + 采纳/锁定闭环 + 对比闭环」成立；P1 增强可用性；P2 属资产库长期能力，交给后续步骤。

## 五、数据落点建议（产品要求，非实现）

1. **采纳/锁定是可变元数据，必须与 append-only 的 `history.jsonl` 分离**。建议写入项目级可变索引（`assets.json` 或 `manifest.json` 内 assets 段），架构师选型，但产品要求：独立文件、可改写、随项目保存、打开项目时恢复。
2. **索引键必须能唯一定位「一张图」而非「一个节点」**：同一节点会被重跑覆盖（txt2img 写回自身），同一 nodeId 随时间对应多张图。建议键 = 图指纹（`hashRef(imageUrl)` 或 trace 标识）+ 冗余存 nodeId（供保护逻辑回溯到节点）。这是采纳/锁定语义正确性的关键产品要求。
3. **保护行为的双语义**：
   - 图级（采纳/锁定作为「结果」的认可）：角标、搜索过滤、对比面板内展示。
   - 节点级（锁定作为「防顶掉」）：`removeChildren` 跳过锁定产出节点；`_writeBackToSelf` 不覆盖锁定源节点图（新图改走新建产出节点）。
4. **复现数据源**：`node.trace`（source of truth）+ `history.jsonl`（跨会话）。复现只读 trace，不改写 history。
5. **对比面板是瞬时态**，不持久化；面板内产生的采纳/锁定写入 X1 同一数据源后持久化。
6. **采纳的图被后续流程复用**：本期至少保证「已采纳成图可拖入画布作参考图」（现有 history-image 拖拽语义复用）；更完整的「入库成图库」为 P2。

## 六、待确认问题（给主理人和架构师决策）

1. **Q1 复现落点**：复现是「回填原节点运行」还是「新建独立节点运行」？产品推荐**新建独立节点**（不破坏原图、可与原图对比），但多次复现会堆积节点；若回填原节点则旧图必须先入历史可找回（A5）。请架构师定。

4. **Q4 对比对象范围**：本期仅画布选中节点（image-gen 且 imageUrl 非空）；历史图库中不在画布上的图进对比（C7）是否确认为 P1？

6. **Q6 分类口径**：确认本期不做分类 tabs（B8 仅留 category 字段）；花材/场景/成图分类 UI 归入资产库后续步骤（第 4 步）。主理人是否认可？
7. **Q7 撤销范围扩展**：采纳/锁定是否纳入最小撤销/重做（X3，产品建议 P1）？P0 至少保证 dirty + 持久化。
8. **Q8 档案入口现状**：team-lead 提到 cmd-panel 已有「档案」入口（showTrace），但当前代码基线未检索到；复现按钮与档案视图的承载位置请架构师按实际 UI 现状落位（操作条 / 卡片 hover / 档案视图），避免重复造轮子。
