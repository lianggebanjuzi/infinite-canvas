## 1. TL;DR

设置面板改为一供应商一份模型组、全部密钥共享——**数据模型不变、后端零改动**。后端三段路由（早已落地）与前端菜单合并展示（早已落地）不动，只重排设置面板的配置组织。

## 2. 现状核实（三层）

| 层 | 现状 | 本次 |
|---|---|---|
| 后端路由（`unified_api.py`） | 已按三段 `provider:key:model` 精确解析路由，key 删除/停用报错提示 | 零改动 |
| 前端菜单（`api.ts` fetchImageModels） | 已跨 key 合并去重（label「供应商短名-模型名」去 key 名，id 路由第一个 enabled key） | 零改动 |
| 设置面板（`settings-panel.ts`） | **每 Key 独立模型组**（用户体感"一个组一个模型"的根源） | ✅ 主改 |

## 3. 改动内容（commit 4fd152b，仅 2 文件）

- **编辑面板重组**：模型组编辑区（拉取/手动添加/模型增删启停）上移到供应商级（「模型组管理（全部密钥共享）」）；key 卡片瘦身为凭据-only（名称/api_key/启停/删除/测试连接），无模型编辑入口。
- **同步策略 `persistProviderModels`**：模型组任何改动 → 逐个 `updateKey` 复制到该供应商**全部 enabled key** 的 models[]（禁用 key 跳过、单 key 失败不中断）。
- **新增 key 初始化**：models 初始化为当前模型组副本（空则后端默认 []）。
- **兼容**：已有每 key 独立配置的供应商，首次编辑模型组前数据不动。
- 供应商卡片模型计数改跨 key 去重（模型组共享后直接相加会重复计数）。
