## 一、项目信息

| 项 | 值 |
|---|---|
| Language | 中文 |
| Programming Language | TypeScript（前端，Vite 构建 + 原生 DOM 渲染，非 React）+ Python（后端，pywebview 外壳，无边框自绘标题栏） |
| Project Name | infinite-canvas |
| 存储 | 本地文件（settings.json + history.jsonl + 可变资产索引 + 图片保存目录），无账号、无移动端、无 ComfyUI |

**原始需求复述（本次增量范围）**：对已有项目做增量开发，共四块（均已确认为 P0）：

- **Bug 1 · 无边框窗口最大化盖住任务栏**：窗口为 frameless（main.py `create_window(frameless=True)`），WinForms 无边框窗口最大化时覆盖整个屏幕而非工作区。点击顶栏「最大化」按钮或双击顶栏后，窗口盖住 Windows 底部任务栏。期望最大化时窗口边界 = 屏幕工作区（不含任务栏），还原正常；需注意 DPI 缩放与多显示器下工作区获取。
- **Bug 2 · 资产索引保存失败**：在历史图库卡片点「采纳/锁定」后提示「资产索引保存失败」。根因已定位：assets.json 落点依赖 `ProjectAPI.current_project_path`（项目文件保存过才有值），未保存过项目文件时 `_assets_path()` 返回 None → no_path 报错；且生成图片当前落 `tempfile.gettempdir()` 临时目录，无持久落点。期望资产索引与生成图片落点改为**用户设置的图片保存目录**，不再依赖项目文件是否保存过；未配置路径时有明确降级与提示。
- **功能 3 · 历史图库与资产库拆分**：左侧抽屉（left-drawer）现叫「历史图库」，展示全部出图/文本记录（image/text 双 tab）且兼任资产功能（卡片上采纳/锁定角标与按钮，数据在 AssetStore）。期望拆成两个独立入口/抽屉——历史图库保留现状（全部出图/文本记录、搜索、复现、拖入画布），移除或弱化采纳/锁定动作；资产库为新抽屉，只显示已采纳的图（AssetStore 中 adopted 记录），支持取消采纳、锁定/解锁、查看、拖入画布；资产图文件落盘到用户指定目录。
- **功能 4 · 设置面板新增「图片保存路径」**：后端 settings_api 已有 `image_save_path` 字段与 `select_folder()` 接口，image_api.py 也在读该字段，但前端设置面板（settings-panel.ts）没有该 UI，主生成链路（unified_api.py `_save_images_to_local` → tempfile.gettempdir()）也未接入。期望设置面板新增配置项（输入框 + 选择文件夹按钮），保存后写入 settings.json；生成图片与资产落盘到该目录；未设置时给用户明确提示。

**当前基线（已核实，供架构师对照）**：
- **无边框窗口**：`main.py` `webview.create_window(..., frameless=True, easy_drag=False)`；窗口控制 `win_minimize / win_toggle_maximize / win_close`（`win_toggle_maximize` 用 `webview.windows[0].maximize()/restore()` + `self._win_maximized` 标志位）。前端 `src/v1/main.ts bindWindowControls()` 绑定 `#win-min/#win-max/#win-close`，顶栏 dblclick（避开 input/button/.topbar-right）也调 `win_toggle_maximize`。
- **资产索引**：`src/v1/asset-store.ts` 是采纳/锁定单一数据源（X1），`_persist()` → `Backend.saveAssets(list)` → `project_api.save_assets()` → `_assets_path()` 依赖 `current_project_path`，未保存项目返回 `{"status":"error","message":"no_path"}` → 前端 toast「资产索引保存失败」。
- **图片落盘**：`unified_api.py _save_images_to_local / _get_save_dir`：`save_dir` 为空或非法时回退 `tempfile.gettempdir()`；`image_api.py` 已读 `settings['image_save_path']`（save_image_as 等），但主生成链路未接入。
- **历史图库**：`src/v1/ui/history-drawer.ts` 左侧悬浮抽屉（`left-drawer` + `history-grid`），已有 image/text 分区 tab、搜索（prompt/model/tags/outputText）、复现、拖入画布、采纳/锁定角标与 hover 动作（B1/B2/B3/B5/B6/A6 已落地）。
- **设置面板**：`src/v1/ui/settings-panel.ts` 只有供应商管理（列表/添加/编辑/默认绘图模型），**无「图片保存路径」UI**；`src/utils/api.ts` 已封装 `load_settings / save_settings / select_folder` 后端调用，前端可直接使用。
- **AssetStore 记录结构**：`{ key(图指纹 hashRef), nodeId, adopted, locked, tags[], category('成图'), updatedAt }`；采纳自动置锁定（B2）。

## 二、产品定义

### Product Goals（3 个正交目标）

1. **桌面体验正确（窗口行为）**：无边框窗口最大化严格贴合屏幕工作区（不含任务栏），还原/最小化/双击行为一致，多显示器与 DPI 缩放下不越界。对应 Bug 1。
2. **资产有家可归（图片落点）**：生成图片与资产索引落盘到用户指定的图片保存目录，不再依赖项目文件是否已保存；采纳/锁定不再报「资产索引保存失败」；未配置路径时有明确降级与提示。对应 Bug 2 + 功能 4。
3. **图库职责清晰（历史 vs 资产）**：历史图库专注全部出图/文本记录（搜索、复现、拖入画布），资产库专注已采纳的好图（取消采纳、锁定/解锁、查看、拖入画布），两个入口独立、数据同源。对应功能 3。

### User Stories

**Bug 1 · 窗口最大化**
- **W-US1**：As 设计师，I want 点击最大化后窗口只铺满屏幕工作区（不遮任务栏），so that 我随时能看到任务栏并切换应用。
- **W-US2**：As 设计师，I want 在双屏/不同 DPI 缩放的显示器上最大化也正确贴合所在屏工作区，so that 我换显示器使用也不会有窗口越界。
- **W-US3**：As 设计师，I want 最大化后再次点击/双击能正常还原到原位置与尺寸，so that 窗口状态切换可逆、不丢失。

**Bug 2 + 功能 4 · 图片落点**
- **A-US1**：As 设计师，I want 未保存过项目文件时采纳/锁定也能成功保存，so that 我不会被「资产索引保存失败」打断。
- **A-US2**：As 设计师，I want 生成图片保存到我设置的目录而不是系统临时目录，so that 我能找到并长期管理这些图。
- **A-US3**：As 设计师，I want 在设置里配置图片保存路径（输入或选择文件夹），so that 所有生成图片与资产固定落在我选的位置。
- **A-US4**：As 设计师，I want 未配置路径时得到明确、可行动的提示（而不是报错），so that 我知道去哪设置。

**功能 3 · 图库拆分**
- **S-US1**：As 设计师，I want 历史图库专注回看全部出图记录（搜索、复现、拖入画布），so that 我可以找回任何生成结果。
- **S-US2**：As 设计师，I want 有一个独立的资产库只展示我采纳过的好图，so that 我不需要在几百张历史图里翻找优质结果。
- **S-US3**：As 设计师，I want 在资产库里能取消采纳、锁定/解锁、查看大图、拖入画布，so that 资产库是一个可维护的精选集。

## 三、需求池

### 4.2 设置面板「图片保存路径」（功能 4）

放在设置面板头部（供应商列表上方），独立分区：

```
┌─ 设置 · 供应商 ──────────────────────────┐
│ 图片保存路径                              │
│ [ C:\Users\...\我的图片\ICV 输出     ] [选择文件夹] │  ← 输入框 + 按钮（P1）
│ 生成图片与采纳的资产将保存到此目录。        │
│ 未设置时生成图仅临时可用、不落盘。          │
│ ────────────────────────────────────── │
│ 默认绘图模型  [下拉]                      │
│ 供应商列表…                              │
└──────────────────────────────────────────┘
```

交互要点：
- 输入框可手改路径；「选择文件夹」调 `select_folder()` 后回填。
- 保存动作：离开/关闭设置或显式保存时写 `save_settings({...image_save_path})`；校验目录存在/可写（P4）。
- 未配置时输入框占位「未设置」，下方 hint 说明后果（P3 文案）。

## 五、数据落点建议（产品要求，非实现）

1. **图片保存目录是唯一事实落点**：用户设置的 `image_save_path` 同时承担「生成图片」「资产索引」两类文件的落盘；不再依赖项目文件是否保存过（Bug 2 根因解除）。
2. **资产索引文件布局（待架构师选型，见 Q3）**：产品推荐全局单一索引（`<image_save_path>/assets.json` 或子目录内固定文件名），因为资产语义是跨项目的长期素材（v3「资产库优先于画布」）；每项目独立文件亦可，但必须保证未保存项目时仍能落盘。记录内冗余 `projectName`（A5，P1）供溯源。
3. **生成图片命名**：沿用 `_make_filename`（时间戳+微秒）避免重名；保存在图片保存目录根或按日期子目录（架构师定，产品不强制）。
4. **索引键不变**：继续用图指纹 `hashRef(imageUrl)`（唯一定位一张图）+ 冗余 nodeId（保护逻辑回溯），与 incremental-2 的 X1 语义一致。
5. **降级顺序（未配置图片保存路径时）**：资产索引 → 应用数据目录（APP_DIR，与 settings.json 同处）可写，同时 toast 提示用户配置路径；生成图片 → 仍以 base64 回前端（不落盘），toast 提示。

## 六、待确认问题（给主理人和架构师决策）

1. **Q1 最大化实现方式**：贴合工作区用哪种方案——Win32 `SetWindowPos`/`SystemParametersInfo(SPI_GETWORKAREA)` 手动设边界，还是拦截 `WM_GETMINMAXINFO` 约束最大化矩形，还是 pywebview 提供的 native 接口？产品要求最终行为 = 最大化贴合工作区 + 还原正确，实现方式架构师定。
2. **Q2 还原边界与状态同步**：最大化前窗口位置/尺寸记录在哪（后端标志位扩展 vs 前端记忆）？`_win_maximized` 与真实状态脱节（如 Win+↑ 系统级最大化）时如何同步？
3. **Q3 资产索引落点布局**：全局单一 assets.json（多项目共用，产品推荐）vs 每项目独立文件（图片保存目录下按项目名分文件）？跨项目资产如何取舍——同一张图在两个项目都采纳，记录去重还是保留两条？
4. **Q4 历史图库角标去留**：移除采纳/锁定动作后，历史图库卡片上的已采纳/已锁定角标保留（只读，产品建议）还是完全移除？
5. **Q5 资产库入口交互**：并列把手（产品推荐）vs 同一抽屉内 tab 切换？若并列把手改动成本高，抽屉内 tab 是否可接受？
6. **Q6 未配置图片保存路径时的默认行为**：资产索引降级写到哪（APP_DIR？用户文档目录？）；是否在首次采纳/生成时弹设置引导？
7. **Q7 多显示器工作区口径**：最大化以「窗口当前所在显示器」为准（产品建议）还是「主显示器」？Windows 工作区 API 在不同 DPI 下的坐标换算由谁负责（架构师确认前端/后端职责）。
