## 2. 产品目标

**一句话**：让画布上的「线」成为全部数据依赖的唯一真相——图是图（image 纯数据节点）、操作是操作（gen 生成节点、text 文本节点），一切数据显式走线，改前面即可一键重跑后面。

**验收标准**（按三个里程碑，可测量）：

| # | 里程碑 | 验收标准 |
|---|---|---|
| M1 | 文本连图反推 | 拖一张图到画布 → 建 image 节点 → 从图拉出 text 节点（或手动连）→ text 节点输入「描述这张图」→ 运行后结果文本写回 text 节点自身；image-gen 上的 modelType='text' 反推开关从 UI 消失；旧「text 结果偷偷覆盖下游 prompt」旁路不再生效 |
| M2 | 图操分家跑通示例链 | 上传图建 image 节点 → 从 image 拉出 gen 节点（空壳操作卡，无产物大图）→ 运行 gen → 自动新建 image 产物节点（连右侧）；gen 重跑 = 删旧产物 image 节点、建新；原 image 素材节点不被改动 |
| M3 | 改前面一键重跑整条链 | 改链首（换图 / 换上游文本）→ 整条链下游全部标 stale（黄）→ 底栏「运行整条链」按钮 → 按拓扑序顺序跑通、失败停止并提示；锁定 image 产物不被碰 |

**三个正交目标**：
1. **线即真相**：删除旁路与游离，所有数据依赖显式走线，屏幕上的线 = 实际依赖（直接上游一层，不穿透）。
2. **图操分家**：数据（image）与操作（gen）节点形态分离，用户一眼可分；text 为「数据+操作」两职的有意例外。
3. **链可重跑**：改前面 → 一键重跑整条 stale 链，顺序正确、锁定保护不退化。

## 3. 用户故事（园艺电商设计师视角）

1. As 园艺电商设计师，I want 把本地绿植产品图拖进画布就得到一个纯图片素材节点，so that 我能把素材和操作分开管理，不会被一个「又要出图」的生成卡挡住。
2. As 园艺电商设计师，I want 从图片节点拉出一条生成操作卡来出图，so that 我清楚知道「这张图是素材、那条线是出图操作」，不再疑惑这个节点到底是图还是生成器。
3. As 园艺电商设计师，I want 对一张参考图拉 text 节点让它「描述这张图」，so that 我能把场景参考反推成提示词文本、连线喂给下游生成，反推结果看得见、连得清。
4. As 园艺电商设计师，I want 修改前面链首的素材或提示词后一键重跑整条链，so that 我不用手动逐个点运行下游，改完前面整条流水线自动按顺序更新。
5. As 园艺电商设计师，I want 把多个文本节点连到一个生成节点时提示词自动拼接，so that 我能把「主体描述 + 风格描述 + 场景描述」分开维护、组合使用，不用复制粘贴进一个大框。

## 4. 节点语义说明（本次改造灵魂）

| 维度 | image（纯数据图） | text（文本） | gen（生成操作） |
|---|---|---|---|
| 核心角色 | **数据节点** | 数据 + 操作（**有意例外**） | **操作节点** |
| 可运行？ | **否**（纯数据，无运行动作） | **是**（上游输入 → 文本模型 → 结果写回自身） | **是**（上游输入 → 生成模型 → 永远吐新 image 节点） |
| 输入（走线） | 无上游（仅作链首素材） | 上游图（反推：图 → 描述文本）+ 上游文（可选，拼进 user prompt）+ 用户命令 | 上游图（参考图）+ 上游文（多个 text 节点 prompt 按连线顺序 / 上游 id 序**拼接**） |
| 输出（走线） | 输出图（imageUrl）→ 下游取为参考图 / 输入图 | 输出文本（outputText）→ 下游 gen 取为 prompt 原料 | **不输出图**；产物 = 新建 image 节点（连右侧） |
| 拖放 / 上传 | 上传图 / 拖图 = 建 image 节点（交互入口沿用 file-input + 画布拖放，仅建的类型变化） | 手动新建 / 拖入画布 | 从 image 节点拉出 / 右键新建 / 扩图预填 |
| 右键操作 | 采纳、锁定、复制、删除、连线、**扩图**（自动建 gen 预填） | 编辑、运行、连线、删除 | 运行、重跑、连线、删除；**不显示产物大图** |
| 卡片形态 | 缩略图 + trace（生成档案）+ 锁定 / 采纳角标 | 文本卡片 + outputText + 指令输入 | **空壳操作卡**：状态色 / 流光 + 最近一次产物缩略图（标注「产物在右侧 image 节点」）+ prompt/参数 chip + 发送 |
| 产物归属 | 自身即产物（imageUrl） | 自身即产物（outputText） | 无自身产物；产物永远在新建 image 节点上 |
| trace 归属 | **挂 image 节点**（记录「这张图怎么来的」） | 无（轻量记录即可） | **不挂 trace**（操作不记档案） |
| 锁定保护 | **锁在 image 节点上**（gen 重跑不碰锁定产物） | 不适用 | 无锁定（操作卡本身无产物） |
| compare-panel | 可对比对象 = image 节点（有图即可比） | 不可对比 | 不可对比 |

**关键语义约束**：
- **一切走线**：所有数据（图、文）显式走线，线 = 全部依赖真相；无旁路覆盖、无游离节点。
- **数据只取直接上游，不穿透**：A→B→C，C 只取 B 的输出；分家后链是 数据→操作→数据→操作，操作节点的直接上游就是数据节点，**一层天然够用**。
- **text 是「数据+操作」两职的有意例外**：文本无「自身变产物」歧义（结果写回自身卡片），与「图操分家」原则不冲突；文档声明，避免施工者困惑（对齐审查意见三.2）。
- **gen 永远吐新 image 节点**：不写回自身、不清空、不变成图；这是「空壳操作卡」的根基。
- **反推归位**：反推 = 图 → text 节点 → 描述文本（不再是 image-gen 上的开关、不再是游离节点）。

## 6. 交互变化描述（文字稿，非高保真）

### 6.1 上传 / 拖图建 image 节点
- 现状：拖图 / 文件选择建 image-gen 节点并塞图（图与生成器同体）。
- 改造后：交互入口不变（file-input + 画布拖放），但新建的是 **image 纯数据节点**——卡片显示缩略图 + 锁定 / 采纳角标 + trace；无运行按钮、无指令面板运行动作。右键提供：采纳、锁定、复制、删除、连线、**扩图**。

### 6.2 从 image 拉 gen
- 从 image 节点右侧连接点拉出 → 新建 gen 节点并自动连好上游图（作为参考图输入）。
- gen 卡片是**空壳操作卡**：无产物大图主视觉，只显示状态色 / 流光；可显示最近一次产物缩略图但标注「产物在右侧 image 节点」；卡片带 prompt / 模型 / 比例 / 分辨率 / 张数 chip + 发送。
- 运行 gen → 自动在右侧新建 image 产物节点（含 trace）；gen 自身保持空壳。

### 6.3 反推走线
- 删除 image-gen 上的 modelType='text' 反推开关（chip 消失）。
- 反推 = 从 image 节点拉出 **text 节点**并连线：text 接收上游图，命令如「描述这张图」，运行后结果文本写回 text 节点自身。
- 文本流全部走线：text 输出 → 连到 gen → 作为 prompt 原料（多个文本上游自动拼接）；不再有「偷偷覆盖下游 prompt」的旁路。
- 用户体感：屏幕上看到的每条线都代表真实依赖，反推结果看得见、连得清。

### 6.4 空壳操作卡（gen）
- gen 节点永远不显示产物大图：视觉上「数据（图）与操作（生成）」一眼可分。
- 状态色 / 流光表达运行状态（idle / run / done / stale / fail 五态沿用）；最近一次产物缩略图仅作提示，标注产物位置。

### 6.5 一键重跑 stale 链
- 底栏新增「运行整条链」按钮：收集全部 stale 节点 → 拓扑排序 → 按序运行（上游先跑、失败停止）。
- 改链首（换图 / 换上游文本）→ 全链下游变黄 → 点一键 → 整条链按序更新。gen 重跑会顶掉旧产物 image 节点并新建；锁定产物不碰。

### 6.6 扩图入口
- image 节点右键「扩图」→ 自动新建 gen 节点并预填：已连上游图 + outpaint 参数（比例等）→ 运行即扩图出图（产物为新建 image 节点）。
